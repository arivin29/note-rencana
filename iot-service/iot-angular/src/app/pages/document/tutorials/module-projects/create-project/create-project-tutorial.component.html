Create New Project Tutorial membuat project baru dan konfigurasi settings

Apa itu Create Project?

Create Project adalah fitur untuk menambahkan project baru ke dalam sistem IoT platform. Project berfungsi sebagai container logis untuk mengelompokkan beberapa Nodes (perangkat IoT) yang terkait, memudahkan manajemen, monitoring, dan reporting berdasarkan project scope. Proses create project meliputi input informasi dasar project, assign owner (tenant), set location, dan configure initial settings.

Form Create New Project dengan field Project Code, Name, Owner selection, Location, Description, dan Status configuration

Form Fields
  • Project Code: Unique identifier (auto-generated atau manual input, e.g., PROJ-001)
  • Project Name: Nama deskriptif project (required, e.g., "Smart Building Jakarta")
  • Owner: Tenant yang memiliki project (dropdown selection, required untuk multi-tenant)
  • Location: Physical location instalasi (address atau GPS coordinates, optional)
  • Description: Tujuan, scope, dan notes project (optional, textarea field)
  • Status: Active (default) / Inactive (radio button atau toggle)
  • Tags: Category labels untuk filtering (optional, multi-select chips)
Kenapa Penting?
  • Structured Organization: Group related devices by project untuk easier management
  • Access Control: Assign user permissions per-project untuk granular security
  • Reporting & Analytics: Generate project-specific telemetry reports dan KPIs
  • Budget Tracking: Monitor operational costs dan ROI per-project
  • Lifecycle Management: Track project dari deployment hingga decommissioning
  • Scalability: Support multi-tenant environments dengan clear project boundaries

Cara Membuat Project Baru

Langkah-langkah Create Project
  1. Access Projects List
    Navigate ke Projects menu di sidebar → Projects List page terbuka
  2. Click "Create New Project" Button
    Di top-right corner, klik button → Modal dialog atau form page terbuka dengan Create Project form
  3. Fill Project Information
    Complete form fields (details explained di section Features below)
  4. Select Owner (Multi-Tenant)
    Dari dropdown Owner, pilih tenant yang akan own project ini → Required untuk multi-tenant environment, auto-filled untuk single-tenant
  5. Configure Location (Optional)
    Input installation address atau klik map picker untuk set GPS coordinates
  6. Set Status
    Pilih initial status:
    • Active: Project ready untuk assign nodes (recommended for new projects)
    • Inactive: Project created but not operational yet (untuk pre-deployment setup)
  7. Submit & Verify
    Klik button → System validates input → Success notification muncul → Redirect ke Project Detail page atau kembali ke Projects List → New project visible dengan status badge
Permission Required

Note: Only users dengan role Admin, Project Manager, atau Owner Admin yang dapat create projects. Regular users tidak memiliki permission untuk create projects untuk security dan data integrity reasons.

Form Fields Detail

1. Project Code
Property Description
Type Text input (alphanumeric, uppercase recommended)
Required ✅ Yes (must be unique across all projects)
Auto-Generation ✅ Available - System generates PROJ-001, PROJ-002, etc. (sequential counter)
Manual Input ✅ Allowed - User can override auto-generated code dengan custom format (e.g., JKT-HQ-2025)
Validation
  • Min length: 3 characters
  • Max length: 20 characters
  • Allowed: A-Z, 0-9, dash (-), underscore (_)
  • No spaces, no special chars (except dash/underscore)
  • Uniqueness check (real-time validation saat typing)
Example PROJ-001, JKT-SMART-BUILDING, FACTORY_A
2. Project Name
Property Description
Type Text input (free text, user-friendly label)
Required ✅ Yes (cannot be empty)
Validation
  • Min length: 3 characters
  • Max length: 100 characters
  • Allowed: All characters (UTF-8 support untuk international names)
  • No uniqueness requirement (dapat duplicate names, karena Code yang unique)
Best Practices
  • Use descriptive names: "Smart Building Jakarta HQ" vs "Project 1"
  • Include location: "[Location] - [Purpose]" format
  • Consistent naming convention: All caps, Title Case, atau lowercase
Example "Smart Office Jakarta", "Factory Temperature Monitoring", "Warehouse IoT Deployment - Surabaya"
3. Owner (Tenant)
Property Description
Type Dropdown select (populated from Owners/Tenants list)
Required ✅ Yes (multi-tenant) / Auto-filled (single-tenant)
Options List semua active owners dengan format:
[Owner Code] - [Owner Name] (e.g., "OWN-001 - PT. Smart IoT Indonesia")
Permission
  • Super Admin: Can select any owner
  • Owner Admin: Can only select their own owner
  • Project Manager: Can select owners they're authorized for
Dependency Owner selection affects:
  • Available nodes untuk assignment (only nodes owned by selected owner)
  • User access permissions (users assigned to owner dapat access project)
  • Billing & reporting (costs attributed to selected owner)
4. Location
Property Description
Type Text input atau Map Picker (dual input mode)
Required ⚠️ Optional (recommended untuk field deployments)
Input Methods
  • Text Input: Type address manually (e.g., "Jl. Sudirman No. 123, Jakarta")
  • Map Picker: Click map icon → Interactive map opens → Click location → Lat/Long auto-filled → Address reverse-geocoded (if API available)
  • GPS Coordinates: Direct input format lat, long (e.g., "-6.2088, 106.8456")
Validation
  • Max length: 255 characters (untuk text address)
  • GPS format validation: -90 to 90 (lat), -180 to 180 (long)
Use Cases
  • Field technician navigation untuk maintenance
  • Geographic reporting (projects by region)
  • Disaster recovery planning (proximity analysis)
  • Map visualization di dashboard
5. Description
Property Description
Type Textarea (multi-line text input)
Required ⚠️ Optional (recommended untuk documentation purposes)
Validation
  • Max length: 1000 characters
  • Markdown support (jika implemented) untuk formatting
What to Include
  • Purpose: Tujuan project (e.g., "Monitor temperature & humidity di warehouse")
  • Scope: Coverage area atau number of nodes (e.g., "10 nodes covering 5 floors")
  • Timeline: Deployment schedule (e.g., "Phase 1: Jan 2025, Phase 2: Mar 2025")
  • Stakeholders: Key contacts atau departments involved
  • Notes: Special considerations atau limitations
Example "IoT monitoring system untuk mengawasi suhu & kelembaban di 3 gudang penyimpanan. Target: 15 nodes (5 per gudang). Deployment: Q1 2025. PIC: Ahmad (Ops Manager)."
6. Status
Property Description
Type Radio buttons atau Toggle switch
Required ✅ Yes (default: Active)
Options
  • Active: Project operational, dapat assign nodes, telemetry flows normally
  • Inactive: Project created tapi not operational, nodes tidak dapat send telemetry
Behavior
  • Active: Visible di dashboard, included in reports, alerts enabled
  • Inactive: Hidden dari dashboard (optional), excluded dari active reports, alerts disabled
Recommendation Set to Active untuk new projects yang ready untuk deployment. Use Inactive hanya untuk pre-deployment testing atau temporarily disable project.
7. Tags (Optional)

Feature: Multi-select chips untuk category labels

Purpose: Filter projects by tags (e.g., "Production", "Testing", "Temperature Monitoring")

Example Tags: Production Critical IoT

Validation & Error Handling

Common Validation Errors:
Error Cause Solution
Project Code already exists Duplicate code detected (codes must be unique) Change code ke nilai yang unique atau use auto-generation
Project Name required Name field empty Fill name field dengan descriptive project name
Owner not selected Multi-tenant environment requires owner selection Select owner dari dropdown
Invalid GPS coordinates Latitude/Longitude out of valid range Verify coordinates: Lat (-90 to 90), Long (-180 to 180)
Description too long Description exceeds 1000 characters Shorten description atau move details to project documentation
Permission denied User role tidak authorized untuk create projects Contact admin untuk request Project Manager role
Real-Time Validation
  • Project Code: Uniqueness check saat typing (debounced API call every 500ms)
  • Field Indicators: Green checkmark (✅ valid), Red X (❌ invalid) beside fields
  • Error Messages: Displayed below field dengan specific guidance
  • Submit Button: Disabled until all required fields valid

After Creating Project

Recommended Next Steps
  1. Assign Nodes to Project
    Navigate ke Project Detail → "Nodes" tab → Click "Assign Nodes" → Select unpaired nodes atau move existing nodes dari other projects
  2. Configure Sensors
    For each assigned node → Configure sensor types, channels, calibration settings
  3. Set Alert Rules
    Configure threshold-based alerts untuk sensor readings (e.g., Temperature > 30°C)
  4. Assign Users
    Grant access permissions ke users yang need to monitor or manage project
  5. Monitor Dashboard
    View Project Detail dashboard untuk real-time telemetry, node health, dan alerts

Pro Tips
  • Use Consistent Naming: Adopt company-wide naming convention untuk Project Codes dan Names (e.g., "[Location]-[Type]-[Year]" → JKT-MONITORING-2025)
  • Plan Project Structure: Group nodes by logical criteria (location, function, department) untuk easier management di large deployments
  • Document Thoroughly: Fill Description field dengan comprehensive info untuk future reference (especially useful ketika handover ke new team members)
  • Use Tags Wisely: Create standardized tag taxonomy untuk consistent filtering across projects (e.g., "Critical", "Production", "Testing", "Temperature", "Humidity")
  • Start with Inactive: For large deployments, create project dengan status "Inactive", assign & configure all nodes first, then activate project ketika ready untuk production
  • Verify Owner: Double-check owner selection before submit (changing owner later may require admin intervention)
  • Save Location Data: Even jika optional, always input location data untuk future operational needs (maintenance, expansion planning, disaster recovery)
