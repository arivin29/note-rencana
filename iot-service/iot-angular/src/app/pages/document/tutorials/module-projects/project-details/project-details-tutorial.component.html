Apa itu Project Detail View?

Project Detail View adalah halaman dashboard monitoring lengkap untuk satu project specific, menampilkan snapshot statistics, status deployment, daftar nodes, sensors, alerts, geofence mapping, dan operations team information.

Project-Level Dashboard

Project adalah container/grouping untuk nodes & sensors dalam satu deployment area:

  • Example 1: "Factory A - Water Treatment" project dengan 20 nodes monitoring water quality
  • Example 2: "Smart City - Zone B" project dengan 50 nodes monitoring traffic & pollution
  • Example 3: "Farm IoT - Sector 3" project dengan 15 nodes monitoring soil & irrigation
Kenapa Penting?
  • Centralized Monitoring: All project resources dalam satu dashboard
  • Quick Statistics: Instant view total nodes, sensors, locations, alerts
  • Status Tracking: Active/Maintenance status, last sync time, uptime
  • Geographic View: Map widget showing node locations dengan geofence boundaries
  • Owner Context: Link to owner company untuk multi-tenant scenario
  • Operations Info: Team assignments, deployment history, maintenance schedule

Cara Akses Project Detail View

Ada beberapa cara untuk mengakses Project Detail View:

Via Project List (Most Common)
  1. Buka IoT → Projects menu
  2. Klik pada baris project (anywhere) atau tombol View Detail (eye icon)
  3. Project detail dashboard akan terbuka
Via Owner Detail View
  1. Open Owner Detail View
  2. Scroll ke Projects section
  3. Klik project name atau View button
Via Dashboard Widget
  1. Dari Main Dashboard, klik project name di widget
  2. Direct link ke project detail view
Via Direct URL

Akses langsung via browser (if you know project UUID):

https://your-domain.com/iot/projects/{{ '{' }}projectUUID{{ '}' }}

Interface & Features Overview

Interface Project Detail View dibagi menjadi beberapa section besar:

Header Section
  • Breadcrumb: IoT → Projects → {{ '{' }}ProjectName{{ '}' }}
  • Page Title: Project {{ '{' }}ProjectName{{ '}' }}
  • Action Buttons:
    • Export Report - Download project summary report
    • Force Sync - Trigger manual data sync dari all nodes
    • More Actions - Schedule maintenance, assign owner admin, archive project
    • Back - Return to projects list
Project Snapshot Card (Main)
  • Status Badges:
    • Active (green) / Maintenance (yellow) / Archived (gray)
    • Last sync timestamp
    • Primary location with map marker icon
  • Project Metadata:
    • Owner: Company name, industry, email
    • Deployment: Live since date, area type (Factory/Smart City/Farm/etc)
    • Data Window: Streaming protocol (MQTT/HTTP), data retention period
  • Statistics Cards (4 Clickable Stat Links):
    • Devices: Total nodes count, online count → Click navigate to Nodes list (filtered by project)
    • Sensors: Total sensors count, offline count → Click navigate to Sensors explorer
    • Locations: Deployment sites count → Click navigate to Telemetry view
    • Alerts: Active alerts count → Click navigate to Alerts queue
  • Footer Actions:
    • Last deployment info (timestamp & actor)
    • Deploy Update button
    • Edit Project button (navigate to edit form)
Operations & Team Card (Right Sidebar)
  • Team Members List: Assigned engineers/operators dengan roles
  • Contact Information: Primary contact for project
  • Maintenance Schedule: Next scheduled maintenance date
  • SLA Status: Service level agreement compliance
Geographic Map Widget
  • Node Markers: All nodes dengan GPS coordinates ditampilkan on map
  • Geofence Boundary: Project area boundary (polygon)
  • Color Coding: Green (online), Yellow (warning), Red (offline)
  • Interactive: Click marker untuk quick node info popup
  • Zoom/Pan: Navigate around deployment area
Recent Activity Timeline
  • Deployment Events: Node added, sensor configured, firmware updated
  • Alerts History: Recent alerts triggered & resolved
  • Maintenance Logs: Scheduled maintenance completion records
  • Configuration Changes: Project settings modified audit trail

Cara Menggunakan

Melihat Project Information
  1. Buka project detail page (via project list atau owner detail)
  2. Check Project Snapshot card untuk overview:
    • Status badge: Verify project Active atau Maintenance
    • Last Sync: Check timestamp - jika > 1 hour, may indicate connectivity issue
    • Location: Primary deployment site
  3. Review Statistics Cards:
    • Devices: Total & online count - low online % = investigate connectivity
    • Sensors: Total sensors deployed - verify matches expected
    • Locations: Deployment sites - multi-location projects may have distributed nodes
    • Alerts: Active count - if > 0, investigate alert queue
  4. Check Owner info untuk company context & contact
  5. Scroll down untuk see geographic map & activity timeline

Dashboard auto-loads fresh data on page load - F5 refresh untuk latest stats

Navigate ke Filtered Resource Views

Statistics cards adalah clickable links ke filtered views:

  1. Click "Devices" card:
    • Navigate to Nodes List
    • Auto-filtered by projectId
    • Shows only nodes belonging to this project
    • Can further filter by status, location, model
  2. Click "Sensors" card:
    • Navigate to Sensors Explorer
    • Auto-filtered by project's nodes
    • Shows all sensors from all nodes in project
  3. Click "Locations" card:
    • Navigate to Telemetry Streams
    • Pre-filtered by project
    • View real-time telemetry data
  4. Click "Alerts" card:
    • Navigate to Alert Queue
    • Filtered by project alerts
    • Review & acknowledge active alerts

Benefit: Quick drill-down dari high-level stats ke detailed resource views

Edit Project Configuration
  1. Klik tombol "Edit Project" di footer snapshot card
  2. Navigate to Project Edit Form
  3. Modify fields yang perlu diubah:
    • Project Name: Rename project
    • Area Type: Change category (Factory/Smart City/Farm/etc)
    • Status: Set Active/Maintenance/Archived
    • Owner: Reassign to different owner (if multi-tenant)
    • Geofence: Update boundary polygon coordinates
    • Description: Add/modify project description
  4. Klik Save
  5. Navigate back to project detail - changes reflected

Note: Changing owner akan affect user access permissions - notify affected users

Force Sync Project Data

Trigger manual sync untuk all nodes in project:

  1. Klik "Force Sync" link di header
  2. Confirmation dialog akan muncul:
    • "Force sync will query all {{ '{' }}nodeCount{{ '}' }} nodes immediately"
    • "This may cause network spike. Continue?"
  3. Klik OK untuk confirm
  4. System akan:
    • Send sync command ke all nodes via MQTT/HTTP
    • Wait for nodes to respond dengan latest telemetry
    • Update database dengan fresh data
    • Refresh dashboard statistics
  5. Monitor "Last Sync" badge - should update to current time

Use Force Sync when suspecting stale data atau after bulk node configuration changes

Export Project Report
  1. Klik "Export Report" link di header
  2. Export dialog muncul dengan options:
    • Format: PDF, Excel, CSV
    • Include: Statistics, Nodes list, Sensors list, Alerts history, Telemetry summary
    • Date Range: Last 7 days, 30 days, Custom range
  3. Select export preferences
  4. Klik Generate Report
  5. File akan download ke browser downloads folder

Use Case: Monthly reports untuk management, audit documentation, client deliverables

View Geographic Map & Geofence

Visualize node deployment locations:

  1. Scroll to Geographic Map Widget
  2. Map akan show:
    • Node Markers: All nodes dengan GPS coordinates
    • Color Coding:
      • Green = Online & healthy
      • Yellow = Warning/degraded
      • Red = Offline/critical
      • Gray = Maintenance mode
    • Geofence Polygon: Project boundary area (blue outline)
  3. Interact with map:
    • Click marker untuk quick node info popup (code, status, last seen)
    • Zoom in/out dengan mouse wheel atau +/- buttons
    • Pan around dengan drag
    • Toggle layers (satellite/terrain/street view)
  4. Geofence Alerts:
    • Nodes outside geofence highlighted in orange
    • Indicates possible GPS drift atau unauthorized movement

Note: Only nodes dengan GPS coordinates akan muncul on map

Schedule Project Maintenance
  1. Klik More Actions dropdown di header
  2. Select "Schedule Maintenance"
  3. Maintenance form muncul:
    • Maintenance Type: Routine/Emergency/Upgrade
    • Scheduled Date: Date picker
    • Duration: Estimated hours
    • Assigned Team: Select engineers/technicians
    • Description: Maintenance scope & tasks
    • Auto-set Status: Checkbox - automatically set project to Maintenance mode during window
  4. Klik Schedule
  5. Maintenance event added to timeline & calendar
  6. Assigned team will receive notification

Maintenance mode suppresses alerts untuk prevent false alarms during work

Memahami Project Data Structure

Hierarchy: Owner → Project → Nodes → Sensors
Owner (ADHI WATER)
└── Project (Factory A - Water Treatment)
    ├── Node 1 (ESP-WTP-01)
    │   ├── Sensor: Power Meter
    │   │   ├── Channel: voltage_l1
    │   │   ├── Channel: current_l1
    │   │   └── Channel: power_l1
    │   └── Sensor: Flow Meter
    │       └── Channel: flow_rate
    ├── Node 2 (ESP-WTP-02)
    │   └── Sensor: pH Sensor
    │       └── Channel: ph_value
    └── Node 3 (ESP-WTP-03)
        └── Sensor: Temperature Sensor
            └── Channel: water_temp

Project adalah container untuk logically group nodes dalam same deployment area

Project Level Fields
  • Project Name: Human-readable identifier (Factory A - Water Treatment)
  • idProject: Database UUID untuk API calls
  • Owner: Reference to owner company (multi-tenant isolation)
  • Area Type: Category - Factory, Smart City, Farm, Building, Infrastructure
  • Status: Active (operational), Maintenance (scheduled work), Archived (decommissioned)
  • Created At: Deployment date
  • Last Sync: Timestamp of last successful data sync dari any node
  • Geofence: Polygon coordinates defining project boundary
Statistics Calculation Logic
  • Total Nodes: COUNT(nodes) WHERE idProject = this
  • Active Nodes: COUNT(nodes) WHERE idProject = this AND connectivityStatus = 'online'
  • Total Sensors: COUNT(sensors) via nodes in this project
  • Total Locations: COUNT(DISTINCT gps_coordinates) from nodes (or manual location entries)
  • Offline Nodes: Total Nodes - Active Nodes

Contoh Penggunaan

Scenario: Monitor Factory IoT Deployment Health

Situasi: Daily morning check untuk Factory A water treatment project

Langkah:

  1. Open project detail view (via project list atau dashboard bookmark)
  2. Quick Health Check:
    • Status badge = Active ✅
    • Devices: 20 total, 19 online (95% uptime) ✅
    • Alerts: 1 active ⚠️
    • Last Sync: 5 minutes ago ✅
  3. Investigate alert:
    • Click "Alerts" card (shows 1 active)
    • Navigate to Alert Queue
    • Find alert: "pH sensor reading out of range (pH 8.5, threshold 6-8)"
    • Acknowledge alert & assign to technician
  4. Check offline node:
    • Click "Devices" card
    • Filter by status = Offline
    • Find ESP-WTP-15 offline (last seen 2 hours ago)
    • Open node detail → connectivity logs show power loss
    • Schedule field visit untuk investigate
  5. Export daily report untuk manager

Result: Issues identified & assigned dalam < 5 minutes daily check

Scenario: Verify New Node Deployment

Situasi: Tech deployed 5 new nodes di expansion area, verify on system

Langkah:

  1. Open project detail view
  2. Check statistics:
    • Before: 20 nodes
    • After: Wait for sync... should become 25 nodes
  3. If not updating:
    • Click "Force Sync"
    • Wait 30 seconds untuk nodes to report
    • Refresh page
  4. Verify on map:
    • Scroll to geographic map widget
    • Check 5 new markers muncul di expansion area
    • Markers should be green (online)
    • Click each marker untuk verify node codes match deployment list
  5. Click "Devices" card → filter by "Created Today" untuk see new nodes
  6. Document deployment completion timestamp

Map visualization helps verify physical placement matches GPS coordinates

Scenario: Prepare for Scheduled Maintenance

Situasi: Quarterly calibration maintenance besok, prepare project

Langkah:

  1. Open project detail view
  2. Klik More Actions → Schedule Maintenance
  3. Fill maintenance form:
    • Type: Routine
    • Date: Tomorrow 08:00 - 16:00 (8 hours)
    • Team: Technician A, Technician B
    • Tasks: Calibrate all pH sensors, clean flow meters, firmware update
    • ✅ Auto-set Status to Maintenance
  4. Save maintenance schedule
  5. System akan:
    • Send notification ke assigned technicians
    • Automatically change project status to "Maintenance" tomorrow 08:00
    • Suppress alerts during maintenance window
    • Restore to "Active" automatically at 16:00
  6. Export current baseline telemetry report untuk before/after comparison

Result: Maintenance automated, alerts suppressed, team notified

Scenario: Investigate Geofence Violation Alert

Situasi: Received alert "Node ESP-WTP-12 outside geofence boundary"

Langkah:

  1. Open project detail view
  2. Scroll to geographic map widget
  3. Find ESP-WTP-12 marker:
    • Should be highlighted in orange (geofence violation)
    • Located outside blue polygon boundary
  4. Click marker untuk node details:
    • Check GPS coordinates
    • Review last position update timestamp
  5. Possible causes:
    • GPS Drift: Sensor malfunction (common in indoor/urban areas)
    • Unauthorized Movement: Someone moved the node
    • Wrong Geofence: Boundary polygon needs adjustment
  6. Resolution:
    • If GPS drift: Click node → Settings → Disable GPS alerts for this node
    • If moved: Field visit untuk verify & relocate atau update coordinates
    • If wrong geofence: Edit Project → Update geofence polygon

Geofence violations dapat indicate security issues - investigate promptly

Scenario: Generate Monthly Report untuk Client

Situasi: End of month, client meminta operational report

Langkah:

  1. Open project detail view
  2. Klik "Export Report"
  3. Configure export:
    • Format: PDF (client-friendly)
    • Date Range: Last 30 days
    • Include Sections:
      • ✅ Executive Summary (statistics overview)
      • ✅ Uptime Analysis (per node)
      • ✅ Alert History (count, severity, resolution time)
      • ✅ Telemetry Summary (average values, trends)
      • ✅ Maintenance Log (scheduled work completed)
      • ❌ Raw sensor data (too detailed untuk executive report)
  4. Klik Generate
  5. Wait for PDF generation (30-60 seconds untuk large projects)
  6. Download PDF report
  7. Review report contents:
    • Cover page: Project name, owner, reporting period
    • Summary: Key metrics, uptime %, alert count
    • Charts: Telemetry trends, alert distribution
    • Tables: Node list, sensor inventory, maintenance log
  8. Attach to email & send to client

Result: Professional report generated dalam < 2 minutes, ready for client delivery

Tips & Best Practices

Common Pitfalls:
  • Stale "Last Sync": If > 1 hour, investigate connectivity - don't ignore
  • Low online percentage: < 80% online nodes indicates systemic issue (power/network)
  • Ignoring geofence violations: May indicate security breach atau GPS malfunction
  • Not using Force Sync: After bulk config changes, always force sync untuk verify
  • Wrong area type: Affects report categorization & analytics - choose correctly
  • No maintenance scheduling: Ad-hoc maintenance causes unplanned downtime & alert spam
Pro Tips:
  • Bookmark frequently accessed projects: Browser bookmark untuk daily check projects
  • Set baseline expectations: Know normal uptime % untuk detect degradation early
  • Use stat cards untuk navigation: Faster than navigating through menus
  • Schedule maintenance windows: Auto-suppress alerts during known downtime
  • Monitor map regularly: Visual anomalies easier to spot than tables
  • Export reports monthly: Build historical archive untuk trend analysis
  • Force sync after deployments: Verify new nodes immediately
  • Check "Last Sync" first: Quickest health indicator - green flag or red flag
  • Use project status wisely: Maintenance mode prevents alert fatigue
  • Keep owner info updated: Contact details critical untuk emergency escalation
