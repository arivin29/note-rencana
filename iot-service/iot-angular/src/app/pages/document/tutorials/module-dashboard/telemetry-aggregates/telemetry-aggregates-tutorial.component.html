Apa itu Telemetry Aggregates?

Telemetry Aggregates adalah halaman monitoring real-time untuk melihat aggregated sensor data dari semua channels dengan time-based windows (5 menit, 15 menit, 1 jam, 1 hari, 1 bulan). Berbeda dengan Sensor Detail View yang fokus pada satu channel, halaman ini menampilkan overview semua channels sekaligus.

Aggregation = Summarized Telemetry Data

Sistem mengumpulkan raw telemetry readings dan menghitung statistik per time window:

  • Window Start/End: Time range untuk aggregation (e.g., 09:00-10:00 untuk 1 hour window)
  • MIN: Nilai minimum dalam window
  • MAX: Nilai maximum dalam window
  • AVG: Nilai rata-rata (average)
  • LATEST: Nilai terakhir di window
  • Points: Jumlah data points yang di-aggregate
Kenapa Penting?
  • Wide Monitoring: Monitor hundreds of channels sekaligus dalam satu view
  • Time-Based Analysis: Compare data across different time windows (5m vs 1h vs 1d)
  • Trend Detection: Identify increasing/decreasing trends dengan visual indicators
  • Quality Assurance: Quick health check dengan color-coded quality badges
  • Filtering Flexibility: Cascading filters (Owner → Project → Node → Sensor → Channel)
  • Auto-Refresh: Live monitoring seperti Grafana dengan configurable intervals
  • Data Export: Export raw data atau aggregated data (5min/1hour) ke CSV

Cara Akses Telemetry Aggregates

Ada beberapa cara untuk mengakses Telemetry Aggregates page:

Via Main Navigation (Recommended)
  1. Klik menu Telemetry Logs di sidebar kiri
  2. Atau navigate via breadcrumb: IoT → Telemetry
  3. Halaman Telemetry Aggregates langsung terbuka
  4. Default: aggregation 1 Jam, no filters
Via Dashboard Widgets (With Filters)
  1. Owner Detail View: Click "View Telemetry" button → pre-filtered by Owner
  2. Project Detail View: Click "View Telemetry" button → pre-filtered by Project
  3. Node Detail View: Click "View All Telemetry" → pre-filtered by Node
  4. Sensor Detail: Link to view all channels in sensor → pre-filtered by Sensor

Filters dari widget akan otomatis terisi di cascading filters

Via Direct URL with Query Params
http://localhost:4200/iot/telemetry?idOwner={{ '{' }}ownerId{{ '}' }}&idProject={{ '{' }}projectId{{ '}' }}

Supported Query Parameters:

  • idOwner - Filter by owner UUID
  • idProject - Filter by project UUID
  • idNode - Filter by node UUID
  • idSensor - Filter by sensor UUID
  • idSensorChannel - Filter by channel UUID
  • range - Time range (default: 24h)

Interface & Features Overview

Interface Telemetry Aggregates dibagi menjadi beberapa section:

Tampilan halaman Telemetry Aggregates dengan time window tabs, cascading filters, statistics cards, dan data table

Page Header & Action Buttons
  • Page Title: "Telemetry Aggregates" dengan subtitle "Monitoring label agrega sensor channel per window 1 Bulan"
  • Filter Badges: Show active filters (Owner/Project/Node/Sensor/Channel)
  • Auto Refresh Toggle: Enable/disable auto-refresh dengan ON/OFF switch
  • Refresh Interval Dropdown: Select interval (5s/10s/30s/1m/5m/15m)
  • Sync Aggregation Button: Manual refresh data
  • Configure Alerts Button: Quick link to alert configuration
  • Export CSV Dropdown: Export options (Raw/5min aggregate/1hour aggregate)
Time Window Tabs (Aggregation Selection)
  • 5m (5 Menit): Data aggregated per 5-minute windows
  • 15m (15 Menit): Data aggregated per 15-minute windows
  • 1h (1 Jam): Data aggregated per 1-hour windows (DEFAULT)
  • 1d (1 Hari): Data aggregated per daily windows
  • 1M (1 Bulan): Data aggregated per monthly windows

Each tab shows badge dengan aggregation label (e.g., "1 Jam" for 1h)

Cascading Filters Section

5 filter dropdowns dengan dependency chain:

Filter Depends On Effect
Owner None (independent) Loads Projects for selected Owner
Project Owner (optional) Loads Nodes for selected Project
Node Project (optional) Loads Sensors for selected Node
Sensor Node (optional) Loads Channels for selected Sensor
Channel Sensor (required) Filters to single channel telemetry
Statistics Summary Cards (3 Cards)
  • Total Records: Count of aggregated records in selected time range
  • Total Data Points: Global count (all pages) of telemetry points
  • Unique Nodes: Number of distinct nodes in current page
Data Quality Summary
  • 0 Healthy (Green): Values within normal thresholds
  • 0 Warning (Yellow): Values approaching threshold limits (within 10%)
  • 60 Critical (Red): Values outside threshold range

"Current page only" - counts based on visible records

Active Filter Scope Info Card

Shows current filter context:

  • Time Range: "Last 1 Jam" (based on aggregation)
  • Active Filter Scope:
    • "All Data (No Filters)" - no filters applied
    • "Single Channel" - filtered to one channel
    • "All Channels in Sensor" - filtered to one sensor
    • "All Sensors in Node" - filtered to one node
    • "All Nodes in Project" - filtered to one project
    • "All Projects in Owner" - filtered to one owner
  • Records displayed: "Showing 1 to 50 of 4736 records (4,736 data points)"
Telemetry Aggregates Table
Column Description
CHANNEL / SENSOR Channel label (e.g., "pressure") + Sensor type badge (e.g., "LLT198")
NODE Node name (e.g., "DEMO1-00D42390A994")
PROJECT / OWNER Project name (e.g., "Demo-project") + Owner code (e.g., "PT DEVELOPMENT")
UNIT Measurement unit (e.g., "bar")
WINDOW Time range for aggregation (e.g., "16:56 - 16:57" for 5m window)
MIN / MAX Minimum and maximum values in window dengan 2 decimal precision
AVG Average value dengan 2 decimal precision
LATEST Most recent value in window dengan large font emphasis
PTS Number of data points aggregated (e.g., "1 pt")

TREND Icon indicator (↑ Up, ↓ Down, → Flat)

Cara Menggunakan

View All Telemetry Data (No Filters)
  1. Access Page: Navigate to IoT → Telemetry
  2. Default View:
    • Aggregation: 1 Jam (last 1 hour of data)
    • Filters: None (all owners, projects, nodes, sensors)
    • Page size: 50 records per page
  3. Review Statistics Cards:
    • Total Records: e.g., 4,736 aggregated windows
    • Total Data Points: e.g., 4,736 telemetry points
    • Unique Nodes: e.g., 1 node on current page
  4. Check Data Quality: Review Healthy/Warning/Critical counts
  5. Browse Table: Scroll through paginated results

Use Case: System-wide health check, identify all critical sensors

Change Time Window (Aggregation)
  1. Klik salah satu Aggregation Tab di atas filter section:
    • 5m: See last 5 minutes, grouped by 5-minute windows
    • 15m: See last 15 minutes, grouped by 15-minute windows
    • 1h: See last 1 hour, grouped by 1-hour windows (DEFAULT)
    • 1d: See last 24 hours, grouped by daily windows
    • 1M: See last month, grouped by monthly windows
  2. Page automatically reloads with new time range
  3. Table shows aggregated data for selected window size
  4. Statistics cards update to show counts for new time range

Tip: Use 5m/15m for real-time monitoring, 1d/1M for trend analysis

Apply Cascading Filters

Scenario: View telemetry untuk specific project

  1. Select Owner: Choose owner dari dropdown (e.g., "PT DEVELOPMENT")
  2. Project dropdown automatically loads projects for that owner
  3. Select Project: Choose project (e.g., "Demo-project")
  4. Node dropdown automatically loads nodes in that project
  5. Optional: Select specific Node, Sensor, or Channel untuk narrow down further
  6. Table filters automatically to show only matching telemetry
  7. Active Filter Scope card updates to show current filter context

Note: Filters cascade - clearing parent filter clears child filters automatically

Search Telemetry Records
  1. Find Search input box (usually above table)
  2. Type search term:
    • Channel label (e.g., "pressure", "volt_l1")
    • Node name (e.g., "DEMO1")
    • Project name (e.g., "Demo-project")
    • Owner name (e.g., "DEVELOPMENT")
    • Sensor type (e.g., "LLT198")
  3. Table filters client-side (instant search, no reload)
  4. Statistics update to reflect filtered results
  5. Clear search to see all records again

Tip: Combine search dengan filters untuk precise targeting

Enable Auto-Refresh (Live Monitoring)
  1. Klik Auto Refresh toggle di page header (switch OFF → ON)
  2. Toggle turns green when enabled
  3. Optional: Klik refresh interval dropdown dan select interval:
    • 5s - Very fast refresh (high CPU usage)
    • 10s - Fast refresh
    • 30s - Default balanced refresh
    • 1m - Moderate refresh
    • 5m - Slow refresh (low CPU)
    • 15m - Very slow refresh
  4. Data automatically refreshes at selected interval
  5. Last Refresh Time updates after each refresh
  6. Klik toggle again to disable auto-refresh

Use Case: Operations center monitoring, NOC dashboard, live troubleshooting

Manual Sync / Refresh Data
  1. Klik "Sync Aggregation" button di page header
  2. Page reloads with latest telemetry data
  3. Current page resets to page 1
  4. Last refresh timestamp updates

Use Case: Verify latest data after sensor calibration, check if issue resolved

Export Telemetry to CSV
  1. Klik "Export CSV" dropdown button
  2. Select export format:
    • Raw Data: Export all filtered telemetry records as-is (no aggregation)
    • 5min Aggregate: Group data into 5-minute buckets before export
    • 1hour Aggregate: Group data into 1-hour buckets before export
  3. Browser downloads CSV file:
    • Filename: telemetry-raw-{{ '{' }}timestamp{{ '}' }}.csv (or -5min, -1hour)
    • Headers: Channel, Sensor, Sensor Type, Node, Project, Owner, Unit, Window Start, Window End, Min, Max, Avg, Latest, Points, Quality, Trend
  4. Use Cases:
    • Import to Excel for charts
    • Python/R data analysis
    • Client reporting
    • Compliance documentation

Note: Export respects current filters - apply filters before export untuk targeted data

Navigate Pagination
  1. View Pagination Controls: Bottom of table shows:
    • "Showing 1 to 50 of 4736 records"
    • Previous / Next buttons
    • Page numbers (1, 2, 3, ... 95)
  2. Navigate Pages:
    • Klik Next button untuk next page
    • Klik Previous untuk previous page
    • Klik page number untuk jump to specific page
  3. Page size fixed at 50 records (configurable in component)

Tip: Use filters/search untuk reduce total pages instead of browsing all pages

Memahami Aggregated Data

Aggregation Concept

Backend mengumpulkan raw sensor readings dan menghitung statistik per time window:

Example: 1-hour window (09:00 - 10:00)
Raw readings: 9:05 → 25.2°C, 9:15 → 26.1°C, 9:30 → 24.8°C, 9:45 → 25.5°C

Aggregated result:
{{ '{' }}
  "windowStart": "2025-12-24T09:00:00Z",
  "windowEnd": "2025-12-24T10:00:00Z",
  "min": 24.8,        // Minimum value in window
  "max": 26.1,        // Maximum value in window
  "avg": 25.4,        // Average: (25.2 + 26.1 + 24.8 + 25.5) / 4
  "latest": 25.5,     // Last reading in window
  "points": 4         // Number of readings aggregated
{{ '}' }}
Time Window Sizes
Aggregation Window Size Time Range Use Case
5m 5 minutes Last 5 minutes Real-time troubleshooting, live monitoring
15m 15 minutes Last 15 minutes Recent activity review
1h 1 hour Last 1 hour Hourly trends, shift monitoring (DEFAULT)
1d 1 day Last 24 hours Daily performance analysis
1M 1 month Last 30 days Monthly reporting, long-term trends
Quality Badge Logic
Quality Condition Badge
Good value ≥ minThreshold AND value ≤ maxThreshold
AND not near limits		 Good
Warning value within 10% of threshold limits
(approaching min or max)		 Warning
Critical value < minThreshold OR value > maxThreshold Critical

Thresholds configured per channel in Sensor Channel configuration

Trend Icons Explained
  • ↑ Up (Green): Latest value > Average value (increasing trend)
  • ↓ Down (Red): Latest value < Average value (decreasing trend)
  • → Flat (Gray): Latest value ≈ Average value (stable)

Useful untuk quick visual assessment of sensor behavior

Contoh Penggunaan

Scenario: Monitor All Critical Sensors in Real-Time

Situasi: Operations team perlu monitor semua sensors 24/7 di NOC dashboard

Langkah:

  1. Navigate to Telemetry Aggregates page
  2. Select aggregation: 5m (real-time view)
  3. Clear all filters (monitor all projects/nodes)
  4. Enable Auto-Refresh dengan interval 10s
  5. Display page on large NOC screen
  6. Monitor Data Quality summary:
    • If Critical count > 0 → Alert badge shows red
    • Click to filter/search critical sensors
  7. Investigate critical channels immediately via Sensor Detail View

Result: Real-time visibility of system health, immediate issue detection

Scenario: Generate Monthly Report for Client

Situasi: Client meminta monthly performance report untuk their project

Langkah:

  1. Navigate to Telemetry Aggregates
  2. Select aggregation: 1M (monthly view)
  3. Apply filters:
    • Owner: Select client's owner account
    • Project: Select specific project (if multiple)
  4. Review statistics:
    • Total Records: Shows how many monthly aggregates
    • Total Data Points: Shows volume of telemetry collected
  5. Review Data Quality:
    • Healthy: X channels operating normally
    • Warning: Y channels approaching limits
    • Critical: Z channels exceeded thresholds
  6. Export CSV with 1hour Aggregate format
  7. Import to Excel:
    • Create pivot tables untuk per-sensor summary
    • Generate charts (min/max/avg trends)
    • Add comments untuk critical incidents
  8. Package as PDF report dengan executive summary

Benefit: Professional monthly reporting dengan data-driven insights

Scenario: Troubleshoot Intermittent Sensor Issue

Situasi: Pressure sensor reporting intermittent warnings, need to analyze pattern

Langkah Investigation:

  1. Navigate to Telemetry Aggregates
  2. Select aggregation: 1d (daily view untuk see full day pattern)
  3. Apply filters:
    • Node: Select node dengan problematic sensor
    • Sensor: Select pressure sensor
    • Channel: Select specific pressure channel
  4. Analyze table data:
    • Check Window column → identify time periods dengan warnings
    • Check MIN/MAX → see if values spiking or dropping
    • Check Points → if low, possible connectivity issue
    • Check Quality badges → count warning vs critical vs good
    • Check Trend icons → identify if consistently up/down/unstable
  5. Pattern Analysis:
    • Warnings at same time daily? → scheduled process causing spike
    • Random warnings? → sensor calibration drift
    • Low points count? → connectivity/power issue
    • Trend consistently up? → pressure buildup, equipment malfunction
  6. Drill down to Sensor Detail View untuk minute-by-minute analysis
  7. Export CSV untuk detailed offline analysis dengan Python/R

Action: Based on pattern, schedule maintenance, adjust thresholds, or replace sensor

Scenario: Compare Performance Across Multiple Projects

Situasi: Owner has 5 projects, wants to compare overall performance

Langkah:

  1. Navigate to Telemetry Aggregates
  2. Select aggregation: 1d (daily comparison)
  3. Apply filter: Owner only (don't select specific project)
  4. Review table:
    • Sort by PROJECT / OWNER column untuk group by project
    • Count critical sensors per project
    • Compare average quality across projects
  5. Findings Example:
    • Project A: 50 channels, 5 critical (10% failure rate)
    • Project B: 30 channels, 0 critical (0% failure rate - BEST)
    • Project C: 80 channels, 20 critical (25% failure rate - WORST)
  6. Drill down to Project C untuk investigate why high failure rate
  7. Export comparison data untuk management presentation

Result: Data-driven decision on where to focus maintenance resources

Tips & Best Practices

Common Pitfalls:
  • Auto-refresh too fast: 5s interval on slow network causes constant loading - use 30s minimum
  • Browsing all 95 pages: Use filters/search instead of clicking through pages
  • Wrong aggregation for use case: Using 1M for real-time monitoring - use 5m/15m instead
  • Ignoring quality badges: All critical sensors missed - always check Data Quality summary first
  • Exporting without filters: Downloading 10,000 records when only need one project - filter first
  • Not clearing filters: Confused why no data showing - check Active Filter Scope card
  • Comparing different windows: Comparing 5m avg vs 1d avg - use same aggregation untuk fair comparison
Pro Tips:
  • Bookmark filtered URLs: Save frequently used filter combinations as browser bookmarks
  • Use 1h aggregation as default: Good balance between detail and overview
  • Monitor trend icons: Quick visual scan - all ↑ = system warming up, all ↓ = cooling down
  • Check points count: Low points (< 10) may indicate connectivity issues
  • Compare MIN vs MAX: Large gap = high variance = unstable sensor/process
  • Use LATEST for current status: AVG shows historical, LATEST shows now
  • Export 1hour aggregate for reporting: Reduces file size while maintaining insights
  • Combine with Dashboard widgets: Use Telemetry Streams widget untuk overview, then drill here for details
  • Set auto-refresh before meetings: Display live data during project review meetings
  • Use search untuk quick sensor lookup: Type sensor name instead of navigating filters
  • Monitor unique nodes count: Sudden drop may indicate multiple nodes offline
  • Schedule CSV exports: Document monthly exports untuk compliance audit trail
