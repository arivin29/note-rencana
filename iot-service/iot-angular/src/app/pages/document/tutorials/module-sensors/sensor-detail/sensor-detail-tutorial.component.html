Apa itu Sensor Detail View?

Sensor Detail View (atau Channel Telemetry Stream) adalah halaman untuk monitoring telemetry readings dari satu sensor channel specific. Menampilkan time-series data dengan filtering period, status, pagination, dan export CSV capabilities.

Channel = Single Measurement Metric

Dalam IoT hierarchy, channel adalah lowest level measurement unit:

  • Node (ESP32 Device: DEMO1-00D42390A994) → contains multiple Sensors
  • Sensor (Power Meter via RS485) → contains multiple Channels
  • Channel (volt l1, current l1, power l1) → individual metric measurement
  • Reading (220.5V at 2025-12-24 09:27:15) → timestamped data point
Kenapa Penting?
  • Real-Time Monitoring: Track single metric over time (voltage, temperature, pressure, etc)
  • Threshold Alerts: Identify values outside normal range (error/warning status)
  • Data Quality Check: Monitor signal quality percentage (70-100%)
  • Historical Analysis: View telemetry history (today, 7 days, 30 days, custom range)
  • Troubleshooting: Diagnose sensor malfunctions via reading patterns
  • Export for Analytics: Download CSV untuk offline analysis/reporting
  • Channel Management: Edit thresholds, delete channel

Cara Akses Sensor Detail View

Ada beberapa cara untuk mengakses Sensor Detail View:

Via Node Detail View (Most Common)
  1. Open Node Detail View (via Nodes list)
  2. Scroll to Sensors section
  3. Each sensor shows list of channels (e.g., Power Meter → volt_l1, current_l1, power_l1)
  4. Klik channel row atau View button (eye icon) pada channel
  5. Channel Telemetry Stream page terbuka
Via Telemetry Streams Dashboard
  1. Navigate to IoT → Telemetry Streams
  2. Find channel di list (dapat filter by node, sensor type, metric)
  3. Klik channel name atau View Detail button
  4. Direct link ke channel telemetry view
Via Direct URL

Akses langsung via browser (if you know nodeId & channelId):

https://your-domain.com/iot/nodes/{{ '{' }}nodeId{{ '}' }}/sensor/{{ '{' }}channelId{{ '}' }}

Example: /iot/nodes/e3edc0d9-8167-4f50-bee3-06d37bcde3b9/sensor/9f0290bc-1f00-4192-973c-40efecc8f872

Interface & Features Overview

Interface Sensor Detail View menampilkan telemetry stream table dengan filter & pagination:

Channel Telemetry Stream - Monitoring volt l1 sensor readings dengan filtering & pagination

Page Header
  • Breadcrumb: IoT → Nodes → Sensor Detail
  • Channel Title: Channel metric code (e.g., "volt l1")
  • Channel Subtitle: Channel type + Metric name + Node location
  • Action Buttons:
    • Sync Telemetry - Force refresh data dari backend
    • Set Threshold - Configure min/max alert thresholds
    • Edit Channel - Modify channel configuration
    • Delete Channel - Remove channel (with confirmation)
    • Export CSV - Download telemetry data
  • Quick Actions:
    • View Node Detail - Navigate to parent node
    • Configure Alerts - Setup alert rules
    • Assign Sensor Profile - Link to sensor catalog
Information Cards (Top Row)
  • Channel Code Card:
    • Metric code display (e.g., "volt l1")
    • Last sample timestamp
  • Node Location Card:
    • Node: Device code (DEMO1-00D42390A994)
    • Sensor type: Category (voltage)
    • Metric: Channel measurement type (volt l1)
  • Total Records Card:
    • Record count in selected period
    • Period label (7 Hari Terakhir)
  • Unit & Thresholds Card:
    • Measurement unit (VOLT)
    • MIN threshold badge (e.g., MIN 0 VOLT)
    • MAX threshold badge (e.g., MAX 100 VOLT)
    • Alert message (Auto alert di luar rentang aman)
Status Filter Tabs
  • All Status (0): Show all readings regardless of status
  • Online (0): Readings within normal range (green)
  • Warning (0): Readings approaching threshold limits (yellow)
  • Error (0): Readings outside threshold range (red)
  • Offline (0): No data received / sensor disconnected (gray)

Counts update automatically based on filtered data

Filter Section (Data Pembacaan Sensor)
  • Period Dropdown: Select time range
    • Hari Ini (today)
    • Kemarin (yesterday)
    • 7 Hari Terakhir (last 7 days) - Default
    • 30 Hari Terakhir (last 30 days)
    • Bulan Ini (this month)
    • Bulan Lalu (last month)
    • Custom Range (manual date picker)
  • Display Filter Indicators:
    • Window data aktif: Time range being displayed
    • Menampilkan: Status filter (All/Online/Warning/Error/Offline)
    • Status filter: Current selection
Channel Telemetry Stream Table
Column Description
SAMPLE Sequential reading ID/number (descending, latest first)
TIMESTAMP Date & time of reading (YYYY-MM-DD HH:mm:ss format)
NILAI Measurement value dengan unit (e.g., 220.5 VOLT)
STATUS Reading status badge (Online/Warning/Error/Offline dengan color coding)
KUALITAS Signal quality percentage badge (70-100%, color-coded)
CATATAN Notes/alerts if value out of range atau quality degraded
Bottom Section (Pagination & Actions)
  • Records Count: "Showing X to Y of Z records"
  • Rows Dropdown: Select page size (10, 25, 50, 100)
  • Pagination Buttons: Previous, Page numbers, Next
  • Refresh Button: Reload current page data
  • Export CSV Button: Download filtered data to CSV file

Cara Menggunakan

View Channel Telemetry Data
  1. Navigate to Channel:
    • Via Node Detail → Click channel dalam sensor list
    • Or via Telemetry Streams → Click channel name
  2. Review Information Cards:
    • Channel Code: Verify metric code correct (volt_l1)
    • Location: Check node & sensor type
    • Total Records: Count of readings in period
    • Thresholds: Note MIN/MAX range untuk context
  3. Check Status Tabs:
    • If Error count > 0 → indicates readings outside range
    • If Warning count > 0 → approaching limits
    • If Offline count > 0 → sensor connectivity issues
  4. Browse Telemetry Table:
    • Latest readings at top (descending timestamp)
    • Check NILAI column untuk measurement values
    • Check STATUS badges (Green/Yellow/Red/Gray)
    • Check KUALITAS percentage (< 90% may indicate signal issues)
    • Read CATATAN untuk error/warning messages

Default view: Last 7 days, All status, 10 rows per page

Filter Telemetry by Time Period
  1. Klik Period Dropdown (default: "7 Hari Terakhir")
  2. Select desired period:
    • Hari Ini: See today's readings only
    • 7 Hari Terakhir: Last week (good untuk trend analysis)
    • 30 Hari Terakhir: Monthly overview
    • Custom Range: Choose specific start & end dates
  3. Table automatically reloads dengan filtered time range
  4. Total Records card updates to show count in period
  5. Status tabs recalculate counts

Tip: Use "Hari Ini" untuk real-time monitoring, "7 Hari" untuk troubleshooting

Filter by Reading Status
  1. Click Status Tab to filter:
    • All Status: Show everything (default)
    • Online: Only normal readings (green badges)
    • Warning: Only warning readings (yellow badges)
    • Error: Only error readings (red badges) - **Most important for troubleshooting**
    • Offline: Only offline/missing readings (gray badges)
  2. Table filters client-side (instant, no reload)
  3. Pagination resets to page 1
  4. Filter indicator shows: "Status filter: Error" (or selected status)

Use Case: Klik "Error" tab untuk quickly find problematic readings

Navigate Pagination
  1. Change Page Size:
    • Klik ROWS dropdown (default: 10)
    • Select 10, 25, 50, or 100 rows per page
    • Larger page size = less page flipping, more scrolling
  2. Navigate Pages:
    • Klik Previous/Next buttons
    • Or klik page number directly
    • Ellipsis (...) indicates skipped pages
  3. Monitor Progress:
    • Bottom shows: "Showing 1 to 10 of 150 records"
    • Current page highlighted in blue

Tip: Use 100 rows/page untuk quick scan, 10 rows untuk detailed inspection

Export Telemetry Data to CSV
  1. Apply desired filters (period, status)
  2. Klik "Export CSV" button (bottom right)
  3. Browser downloads CSV file:
    • Filename: sensor-{{ '{' }}metricCode{{ '}' }}-{{ '{' }}timestamp{{ '}' }}.csv
    • Example: sensor-volt_l1-2025-12-24T09:27:15.csv
  4. CSV Contains:
    • Headers: ID, Timestamp, Value, Unit, Status, Quality, Notes
    • All filtered records (not just current page)
    • Comma-separated values
  5. Use Cases:
    • Import ke Excel/Google Sheets untuk charts
    • Offline analysis dengan Python/R
    • Backup telemetry data
    • Client reporting/documentation

Result: Complete dataset export untuk external analysis

Edit Channel Threshold Settings
  1. Klik "Set Threshold" button di header
  2. Threshold configuration drawer opens
  3. Modify fields:
    • Min Threshold: Lower alert limit (e.g., 0 VOLT)
    • Max Threshold: Upper alert limit (e.g., 100 VOLT)
    • Precision: Decimal places (e.g., 0.01 untuk 2 decimal)
    • Unit: Measurement unit (VOLT/AMPERE/WATT/etc)
  4. Klik Save
  5. System akan:
    • Update channel configuration
    • Recalculate status for all readings (Error/Warning/Online)
    • Reload telemetry view dengan new status badges
    • Update threshold card (MIN/MAX displays)

Important: Changing thresholds affects alert triggering - coordinate with ops team

Delete Channel (Permanent Removal)
  1. Klik "Delete Channel" button (red button di header)
  2. Confirmation dialog appears:
    • "Are you sure you want to delete channel "volt_l1"?"
    • Lists what will be deleted:
      • Channel configuration
      • All telemetry data
      • Alert rules
    • "This action cannot be undone."
  3. Klik OK to confirm, or Cancel to abort
  4. If confirmed, system:
    • Deletes channel & all related data
    • Redirects to Node Detail View
    • Shows success notification

Warning: Deletion is permanent - all historical telemetry data will be lost!

Memahami Telemetry Data Structure

Sensor Reading Data Model
{{ '{' }}
  "id": 150,                              // Sequential reading number
  "timestamp": "2025-12-24T09:27:15Z",   // UTC timestamp
  "value": 220.5,                         // Measurement value
  "unit": "VOLT",                         // Measurement unit
  "status": "online",                     // Calculated status based on thresholds
  "quality": 95,                          // Signal quality percentage
  "notes": "Mendekati batas warning"     // Optional notes/alerts
{{ '}' }}
Status Determination Logic
Status Condition Badge Color Example (Min=0, Max=100)
Online Min ≤ value ≤ Max
AND quality > 90%		 Green Value = 50V (normal range)
Warning Approaching thresholds
(within 10% of limits)		 Yellow Value = 92V (approaching max 100V)
Error value < Min OR value > Max Red Value = 110V (exceeds max 100V)
Offline No data received
OR quality < 70%		 Gray No reading for 5+ minutes
Quality Percentage Explained
  • 90-100% (Green): Excellent signal - reliable data
  • 75-89% (Blue): Good signal - acceptable data quality
  • 60-74% (Yellow): Degraded signal - may indicate sensor issues
  • < 60% (Red): Poor signal - data unreliable, check sensor/wiring

Quality affected by: signal noise, wiring issues, sensor drift, interference

Contoh Penggunaan

Scenario: Investigate Voltage Spike Alert

Situasi: Received alert "Voltage channel volt_l1 exceeded max threshold (110V > 100V max)"

Langkah Investigation:

  1. Navigate to channel telemetry view (via alert link atau node detail)
  2. Check Error tab count - shows 5 error readings
  3. Click Error tab to filter problematic readings
  4. Review table:
    • Timestamp: 2025-12-24 09:15:00 - Value: 110.2V (Error)
    • Timestamp: 2025-12-24 09:15:30 - Value: 112.5V (Error)
    • Timestamp: 2025-12-24 09:16:00 - Value: 108.3V (Error)
    • Timestamp: 2025-12-24 09:16:30 - Value: 102.1V (Warning)
    • Timestamp: 2025-12-24 09:17:00 - Value: 98.5V (Online)
  5. Analysis:
    • Spike duration: ~2 minutes (9:15-9:17)
    • Peak value: 112.5V (12.5% over limit)
    • Recovery: Gradual return to normal
    • Conclusion: Temporary voltage surge, not equipment failure
  6. Export CSV dengan period "Hari Ini" untuk documentation
  7. Report to electrical team: "Grid voltage surge at 09:15, lasted 2min, peak 112.5V"

Result: Root cause identified - grid power issue, not sensor malfunction

Scenario: Monitor Daily Temperature Pattern

Situasi: Want to analyze daily temperature cycle untuk HVAC optimization

Langkah:

  1. Open temperature channel (e.g., "water_temp" channel)
  2. Set period filter to "Hari Ini"
  3. Set page size to 100 rows untuk full day view
  4. Review table data:
    • 00:00 - 06:00: Temp drops to 18-20°C (night cooling)
    • 06:00 - 12:00: Temp rises to 22-25°C (morning warmup)
    • 12:00 - 18:00: Peak temp 28-30°C (afternoon heat)
    • 18:00 - 24:00: Temp drops to 22-24°C (evening cooldown)
  5. Export CSV dengan full day data
  6. Import ke Excel, create line chart
  7. Insight: Peak temp at 14:00 (2PM), minimum at 05:00 (5AM)
  8. Action: Adjust HVAC schedule to pre-cool at 13:00, reduce power at 05:00

Benefit: Data-driven HVAC optimization → 15-20% energy savings

Scenario: Troubleshoot Poor Signal Quality

Situasi: Sensor readings erratic, suspect wiring issue

Langkah Diagnosis:

  1. Open suspect channel telemetry view
  2. Set period to "7 Hari Terakhir"
  3. Check KUALITAS column:
    • Day 1-3: Quality 95-100% (green) - normal
    • Day 4: Quality drops to 75-85% (blue) - degrading
    • Day 5-7: Quality 60-70% (yellow/red) - poor signal
  4. Pattern Analysis:
    • Progressive degradation over 4 days
    • Not sudden failure → rules out power loss
    • Gradual decline → indicates corrosion atau loose connection
  5. Export CSV untuk detailed analysis
  6. Field Action:
    • Dispatch technician to check wiring
    • Found: Corroded terminal block
    • Fix: Replace terminal, clean connections
  7. After repair:
    • Reload telemetry view
    • Quality back to 95-100% (green)
    • Readings stable again

Result: Quality column helped identify wiring issue before complete sensor failure

Scenario: Adjust Threshold After Calibration

Situasi: After sensor calibration, previous thresholds no longer accurate

Langkah:

  1. Tech team calibrated pressure sensor:
    • Old operating range: 0-100 PSI
    • New operating range: 10-90 PSI (tighter control)
  2. Open pressure channel telemetry view
  3. Current thresholds:
    • MIN: 0 PSI
    • MAX: 100 PSI
  4. Click "Set Threshold" button
  5. Update configuration:
    • MIN Threshold: 0 → 10 PSI
    • MAX Threshold: 100 → 90 PSI
    • Precision: 0.1 (1 decimal place)
  6. Save changes
  7. System recalculates status for all readings:
    • Previous "Online" readings at 5 PSI now show "Error" (below new min 10 PSI)
    • Previous "Online" readings at 95 PSI now show "Error" (above new max 90 PSI)
  8. Threshold card updates: MIN 10 PSI, MAX 90 PSI
  9. Future readings akan use new thresholds untuk alert triggering

Important: Notify ops team of threshold changes to avoid confusion about new alerts

Tips & Best Practices

Common Pitfalls:
  • Ignoring quality percentage: Low quality readings unreliable - don't base decisions on < 70% quality data
  • Not using status filters: Browse 1000 records to find errors - use Error tab instead
  • Wrong time period: Viewing "Hari Ini" when investigating yesterday's alert - always check period filter
  • Deleting channel accidentally: Permanent data loss - always confirm deletion carefully
  • Exporting without filtering: Export all 10,000 records when only need errors - filter first
  • Threshold too tight: Setting MAX=100.0 when readings fluctuate 99-101 causes constant alerts
  • Not checking notes column: Missing important error messages - always read CATATAN field
Pro Tips:
  • Bookmark critical channels: Frequently monitored channels - bookmark URL untuk quick access
  • Use custom range for forensics: Incident at Dec 20 14:00? Use custom period: Dec 20 13:00 - 15:00
  • Export before threshold changes: Backup current data before modifying thresholds
  • Monitor quality trends: Gradual quality decline = early warning of hardware failure
  • Use 100 rows/page for pattern detection: See full day trend without scrolling
  • Check status tabs first: Quick health check - if all tabs show 0, system healthy
  • Combine filters: "Last 7 days" + "Error status" = show week's problems only
  • CSV for reporting: Export → Excel charts → client presentation
  • Notes field for documentation: System auto-generates, but useful untuk troubleshooting context
  • Sync before investigation: Click "Sync Telemetry" untuk ensure latest data loaded

Quick Reference

Status Badge Reference
  • Online - Normal range, good quality (green)
  • Warning - Approaching limits (yellow)
  • Error - Out of threshold range (red)
  • Offline - No data / poor quality (gray)
Period Filter Options
  • Hari Ini: 00:00 today → now
  • Kemarin: 00:00 yesterday → 23:59 yesterday
  • 7 Hari Terakhir: Now - 7 days → now (default)
  • 30 Hari Terakhir: Now - 30 days → now
  • Bulan Ini: 1st of month → now
  • Bulan Lalu: 1st of last month → last day of last month
  • Custom Range: User-specified start & end dates
Keyboard Shortcuts
  • F5 - Refresh page (reload latest telemetry)
  • Ctrl + E - Export CSV
  • Alt + ← - Back to Node Detail
  • ← / → - Previous/Next page (when pagination focused)
