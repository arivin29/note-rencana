Apa itu Sensor Types?

Sensor Types adalah halaman untuk mengelola master data kategori sensor yang digunakan dalam sistem IoT, termasuk unit pengukuran, precision, dan formula konversi.

Apa itu Sensor Type?

Sensor Type adalah template/kategori sensor yang mendefinisikan: jenis sensor (Temperature, Humidity, Pressure, dll), default unit (°C, %, kPa), precision (decimal places), dan conversion formula (jika perlu transformasi data).

Fungsi Utama:
  • Melihat semua sensor types yang tersedia di platform
  • Add new sensor type untuk expand sensor support
  • Edit existing type untuk update unit/precision/formula
  • Define conversion formula untuk sensor non-linear
  • Set precision untuk control data accuracy & storage
  • Standardize unit pengukuran across platform
Use Case: Ketika add sensor baru ke node, Anda pilih Sensor Type (contoh: "temperature") yang automatically set unit (°C), precision (2 decimals), dan conversion formula (jika ada).

Cara Menggunakan

Search Sensor Types
  1. Ketik di Search Box
  2. Anda bisa search by:
    • Category: "temperature", "humidity", "pressure"
    • Unit: "°C", "%", "kPa", "ppm"
    • Formula: Bagian dari conversion formula
  3. Table otomatis filter real-time saat mengetik
  4. Hapus text untuk show all sensor types
Tip: Search "temp" untuk quick find temperature-related sensors!
Add New Sensor Type
  1. Klik button "Tambah Sensor Type"
  2. Drawer akan slide-in dari kanan
  3. Fill in form fields:
    • Category: Sensor category name (lowercase, contoh: "soil_moisture")
    • Default Unit: Unit pengukuran (contoh: "%", "°C", "ppm")
    • Precision: Decimal places (0-5, contoh: 2 untuk 2 decimals)
    • Conversion Formula: (Optional) Formula untuk convert raw data
      Gunakan 'x' untuk raw value, contoh: x * 0.01
  4. Klik "Save"
  5. New sensor type muncul di table
Note: Category name harus unique! System akan reject jika duplicate.
Edit Existing Sensor Type
  1. Cari sensor type yang ingin di-edit di table
  2. Klik button Edit (icon pensil biru) di kolom Actions
  3. Drawer akan open dengan form pre-filled
  4. Update field yang diperlukan:
    • Unit (jika ada standar baru)
    • Precision (jika perlu akurasi lebih/kurang)
    • Conversion Formula (jika ada penyesuaian)
  5. Klik "Save" untuk apply changes
  6. Table akan refresh dengan data terbaru
Common Edit: Update precision dari 1 ke 2 untuk temperature sensors agar lebih akurat.
Delete Sensor Type
  1. Cari sensor type yang ingin dihapus
  2. Klik button Delete (icon trash merah) di kolom Actions
  3. Confirm deletion di popup dialog
  4. Sensor type will be removed dari system
Warning! Hanya delete sensor type yang tidak digunakan oleh sensor aktif! Deleting type yang masih digunakan dapat cause data integrity issues.
Define Conversion Formula

Kapan menggunakan conversion formula?

  • Sensor mengirim raw value yang perlu di-convert
  • Unit conversion (Fahrenheit ke Celsius)
  • Calibration offset atau scaling
  • Non-linear sensor response

Formula syntax:

Gunakan x untuk represent raw value dari sensor

Contoh formula:

  • x * 0.01 - Scale down by 100
  • (x - 32) * 5/9 - Fahrenheit to Celsius
  • x / 10 + 5 - Scale & offset
  • x * x - Quadratic response
Pro Tip: Test formula dengan sample data sebelum deploy ke production sensors!

Memahami Data Sensor Type

Sensor Type Data Structure:
Sensor Type (Template Master)
├── Category: temperature (unique identifier)
├── Default Unit: °C (Celsius)
├── Precision: 2 (decimal places)
│   └── Example: 25.73°C (2 decimals)
│
├── Conversion Formula: x * 0.01
│   └── Raw: 2573 → Converted: 25.73°C
│
└── Used By: All temperature sensors in system
    ├── Node 001 - Sensor T1 (outdoor temp)
    ├── Node 002 - Sensor T2 (indoor temp)
    └── Node 003 - Sensor T3 (water temp)
Common Sensor Categories:
Category Unit Precision Use Case
temperature °C 2 Suhu lingkungan, air, mesin
humidity % 1 Kelembaban udara relatif
pressure kPa 2 Tekanan atmosfer/air
water_level m 2 Ketinggian air di tank/sungai
flow_rate L/min 2 Aliran air/gas
co2 ppm 0 Kualitas udara CO2

voltage V 2 Tegangan listrik/baterai
Precision (Decimal Places) Impact:
Precision: 0

Format: Integer only (25)
Best For: CO2 ppm, count sensors, on/off states
Storage: Minimal (most efficient)

Precision: 1

Format: 1 decimal (25.7)
Best For: Humidity %, basic temperature
Storage: Small

Precision: 2

Format: 2 decimals (25.73)
Best For: Temperature, pressure, pH, voltage
Storage: Medium (most common)

Precision: 3+

Format: 3+ decimals (25.735)
Best For: Scientific instruments, high-precision sensors
Storage: Larger (use only if needed)

Conversion Formula Examples:
Scenario Formula Explanation
Sensor raw 0-1023 x * 0.0977 Convert ADC 10-bit ke 0-100 range
Fahrenheit sensor (x - 32) * 5/9 Convert F ke Celsius
mV ke V x / 1000 Convert millivolt to volt
Offset calibration x - 5.2 Adjust sensor offset error
Scale & offset x * 0.1 + 2 Scale down dan add offset

Contoh Penggunaan

Scenario: Add Soil Moisture Sensor Type

Situasi: Deploy agriculture IoT project perlu soil moisture sensors

Langkah:

  1. Klik "Tambah Sensor Type"
  2. Fill form:
    • Category: soil_moisture
    • Default Unit: %
    • Precision: 1 (1 decimal cukup)
    • Conversion Formula: x * 0.1 (if sensor output 0-1000 untuk 0-100%)
  3. Save → New type ready!
  4. Sekarang bisa add soil moisture sensors ke nodes dengan auto unit & formula

Result: Soil moisture sensor type ready untuk agriculture project

Scenario: Update Temperature Precision

Situasi: Temperature sensor precision 1 decimal tidak cukup akurat

Langkah:

  1. Search "temperature" di sensor types
  2. Klik Edit button
  3. Update Precision: 1 → 2
  4. Save changes
  5. Future temperature sensors akan save dengan 2 decimal precision (25.73°C)

Result: Improved temperature data accuracy untuk better analytics

Scenario: Add Fahrenheit Temperature Type

Situasi: Client di US menggunakan Fahrenheit, perlu support

Langkah:

  1. Klik "Tambah Sensor Type"
  2. Fill form:
    • Category: temperature_f
    • Default Unit: °F
    • Precision: 2
    • Conversion Formula: (x - 32) * 5/9 (convert to Celsius untuk storage)
  3. Save
  4. System akan auto convert Fahrenheit ke Celsius untuk standardized storage

Result: Support Fahrenheit sensors dengan automatic conversion to Celsius

Scenario: Calibrate Sensor with Offset

Situasi: pH sensor selalu read 0.3 terlalu tinggi (calibration error)

Langkah:

  1. Search "ph" sensor type
  2. Klik Edit
  3. Add Conversion Formula: x - 0.3
  4. Save
  5. All pH readings akan automatically adjusted by -0.3
  6. Monitor beberapa readings untuk validate correction

Result: Corrected pH readings tanpa perlu ganti hardware

Scenario: Custom Analog Sensor

Situasi: Custom analog sensor output 0-4095 (12-bit ADC) untuk 0-100 PSI

Langkah:

  1. Create new sensor type:
    • Category: pressure_psi
    • Default Unit: PSI
    • Precision: 1
    • Conversion Formula: x * 0.0244 (4095 → 100, so x/4095*100 = x*0.0244)
  2. Save dan test dengan sample values:
    • Raw: 0 → 0.0 PSI ✓
    • Raw: 2048 → 50.0 PSI ✓
    • Raw: 4095 → 100.0 PSI ✓
  3. Deploy sensors dengan type ini

Result: Custom analog sensor fully integrated dengan proper scaling

Tips & Best Practices

Quick Tips:
  • Use lowercase & underscores untuk category names (temperature_f, soil_moisture)
  • Keep precision reasonable - higher precision = more storage space
  • Test conversion formulas dengan sample data before production
  • Document complex formulas di naming atau external docs
  • Standardize units across platform (prefer SI units: °C, kPa, m)
  • Group related sensors (temp_indoor, temp_outdoor vs just temp1, temp2)
Perhatian:
  • Changing precision: Affects NEW sensor readings only, tidak change historical data
  • Formula errors: Invalid formula = sensor data corrupt! Always validate!
  • Delete restrictions: Cannot delete types used by active sensors
  • Unit consistency: Mixing units (°C & °F) dapat cause confusion - standardize!
  • Over-precision: Precision 5 untuk temperature sensor = overkill & waste storage
Pro Tips:
  • Create sensor type naming convention: {{ '{' }}measurement{{ '}' }}_{{ '{' }}variant{{ '}' }}
  • Use version suffixes untuk breaking changes: temp_v2 instead of modify existing
  • Document formula logic: Keep spreadsheet dengan test cases & expected outputs
  • Monitor data after formula changes untuk detect conversion errors early
  • Prefer linear conversions (simpler, faster) unless sensor truly non-linear
  • Setup alerts untuk sensor readings outside expected range (detect formula issues)
  • Backup sensor types config before major changes
  • Use precision 2 sebagai default untuk most sensors (good balance)
