Apa itu Node Detail View?

Node Detail View adalah halaman dashboard monitoring lengkap untuk satu IoT node specific, menampilkan semua informasi metadata, status connectivity, daftar sensors, sensor channels, telemetry graphs real-time, dan provide full CRUD operations untuk sensors & channels.

Multi-Layer Structure

Node Detail View menggunakan 3-layer hierarchy:

  • Layer 1: Node - IoT gateway/device (ESP32, STM32, LoRa gateway)
  • Layer 2: Sensors - Physical sensors attached to node (power meter, temp sensor, level sensor)
  • Layer 3: Channels - Individual measurement points from sensor (voltage, current, temperature, etc)
Kenapa Penting?
  • Single Pane of Glass: Semua informasi node dalam satu dashboard comprehensive
  • Real-time Monitoring: Live telemetry graphs untuk critical channels (top 4 auto-displayed)
  • Full CRUD: Add, edit, delete sensors & channels without backend coding
  • Status Tracking: Uptime percentage, connectivity status, sensor health, channel status
  • Hierarchical Management: Cascade delete prevention (harus delete channels dulu baru sensor, sensor dulu baru node)
  • Relay Control: Control relay outputs (if node has relay capabilities)

Cara Akses Node Detail View

Ada beberapa cara untuk mengakses Node Detail View:

Via Node List (Most Common)
  1. Buka IoT → Nodes menu
  2. Klik pada baris node (anywhere) atau tombol View Detail (eye icon)
  3. Node detail dashboard akan terbuka
Via Dashboard Widget
  1. Dari Main Dashboard, klik node name di widget
  2. Direct link ke node detail view
Via Direct URL

Akses langsung via browser (if you know node UUID):

https://your-domain.com/iot/nodes/{{ '{' }}nodeUUID{{ '}' }}

Interface & Features Overview

Interface Node Detail View dibagi menjadi beberapa section besar:

Header Section
  • Breadcrumb: IoT → Nodes → {{ '{' }}NodeCode{{ '}' }}
  • Page Title: Node {{ '{' }}NodeCode{{ '}' }} (e.g., "Node ESP-CS-F03")
  • Action Buttons:
    • Edit Node - Edit node configuration
    • Delete Node - Remove node (only if no sensors attached)
    • Back to Nodes - Return to node list
  • Quick Actions Menu:
    • Export Telemetry
    • Force Sync
    • More Actions (Update Payload Mapping, Schedule Maintenance, etc)
Node Information Card
  • Uptime Badge: Percentage uptime (e.g., "Uptime 98.5%")
  • Alerts Badge: Active alerts count (if any)
  • Metadata Sections:
    • Owner: Company name, contact person, industry
    • Project: Project name, area type
    • Device Model: Hardware model, protocol (MQTT/HTTP/LoRa)
    • Firmware: Version, telemetry mode (push/pull), interval
    • Location: Address, coordinates (if GPS available)
    • Maintenance: Last maintenance date
Telemetry Trends (Top 4 Channels)
  • Mini Sparkline Graphs: Last 48 hours data trend for top 4 critical channels
  • Latest Value Display: Current value dengan unit
  • Auto-selected: System automatically pick top 4 most important channels
  • Gradient Area Chart: Smooth curve untuk easy trend visualization
Sensors & Channels List
  • Add Sensor Button: Buka drawer untuk tambah sensor baru
  • Sensor Accordion: Collapsible sections untuk setiap sensor
  • Sensor Header Info:
    • Sensor code/label
    • Catalog name (sensor model)
    • Health badge (Active/Inactive/Maintenance)
    • Protocol channel & sampling rate
    • Edit & Delete buttons
  • Channels Table (inside each sensor):
    • Metric code
    • Sensor type label
    • Unit
    • Latest value
    • Status badge (OK/Warning/Critical)
    • Edit & Delete actions
  • Add Channel Button: Per sensor, untuk tambah channel baru
Right Sidebar
  • Live Telemetry Records: Real-time status updates (Overall Health, Connectivity, Sensors Count, Uptime)
  • Maintenance Timeline: Recent activity log (Install, Config Change, Maintenance, etc)

Cara Menggunakan

Melihat Node Information
  1. Buka node detail page (via node list atau dashboard)
  2. Scroll untuk lihat semua sections:
    • Node Information: Owner, project, device specs, firmware
    • Telemetry Trends: 4 mini graphs untuk critical channels
    • Sensors List: All sensors dengan channels nested
    • Live Telemetry: Right sidebar - current status
    • Maintenance Timeline: Recent activities
  3. Check uptime badge di header untuk quick health status
  4. If alerts active, badge kuning akan muncul dengan count

Dashboard auto-refresh setiap load - data selalu fresh dari backend

Menambah Sensor Baru
  1. Klik tombol "+ Add Sensor" di Sensors section
  2. Drawer form akan muncul dari kanan
  3. Isi form sensor:
    • Sensor Code: Unique identifier (e.g., "SENSOR-PM-01")
    • Sensor Catalog: Pilih dari dropdown (HIRP Power Meter, DHT22, etc)
    • Protocol Channel: RS485 address atau I2C address (optional)
    • Sampling Rate: Dalam seconds (berapa detik sekali baca sensor)
    • Status: Active/Inactive/Maintenance
  4. Klik Save
  5. Drawer close, dashboard auto-reload dengan sensor baru

Result: Sensor baru muncul di list, ready untuk add channels

Edit Sensor
  1. Pada sensor yang mau di-edit, klik tombol Edit (pencil icon kuning)
  2. Drawer form muncul dengan data existing pre-filled
  3. Modify field yang ingin diubah:
    • Change sensor code
    • Update protocol channel (if hardware changed)
    • Adjust sampling rate (faster/slower)
    • Set status (active → maintenance for calibration)
  4. Klik Save
  5. Dashboard auto-reload dengan perubahan

Note: Cannot change sensor catalog setelah dibuat - jika salah catalog, delete & create new

Delete Sensor
  1. Pada sensor yang mau di-delete, klik tombol Delete (trash icon merah)
  2. System akan validate:
    • If sensor has channels → Error: "Cannot delete sensor with channels. Delete all channels first."
    • If sensor has no channels → Proceed dengan confirmation dialog
  3. Confirmation dialog show details:
    • Sensor label
    • Catalog name
    • Warning: "This action cannot be undone"
  4. Klik OK untuk confirm delete
  5. Sensor removed, dashboard auto-reload

Cascade Prevention: Harus delete semua channels dulu sebelum bisa delete sensor

Menambah Channel ke Sensor
  1. Expand sensor accordion (klik sensor header)
  2. Klik tombol "+ Add Channel" di dalam sensor section
  3. Drawer form muncul
  4. Isi form channel:
    • Metric Code: Unique code (e.g., "voltage_l1", "temp_ambient")
    • Sensor Type: Pilih dari dropdown (Temperature, Voltage, Current, etc)
    • Unit: Auto-filled dari sensor type, bisa override (V, A, °C, %)
    • Precision: Decimal places (0-5)
    • Min/Max Threshold: Untuk alert triggering (optional)
    • Status: OK/Warning/Critical
  5. Klik Save
  6. Channel baru muncul di sensor's channel table

Result: Channel ready to receive telemetry data from sensor

Edit Channel
  1. Di channel table, klik tombol Edit (pencil icon)
  2. Drawer form muncul dengan channel data pre-filled
  3. Modify field:
    • Change metric code
    • Update sensor type (if measurement category changed)
    • Adjust precision (more/less decimals)
    • Set new min/max thresholds
    • Change status (OK → Warning if degraded)
  4. Klik Save

Changing precision affects how telemetry data is displayed & stored

Delete Channel
  1. Di channel table, klik tombol Delete (trash icon)
  2. Confirmation dialog shows:
    • Channel ID
    • Metric code
    • Sensor label (parent sensor)
    • Warning: "Will permanently remove all telemetry history for this channel"
  3. Klik OK untuk confirm
  4. Channel removed, telemetry history deleted

Data Loss Warning: All historical telemetry data for this channel will be permanently deleted

Update Payload Mapping

Untuk node yang menggunakan Node Profile:

  1. Klik More Actions dropdown di header
  2. Pilih "Update Payload Mapping"
  3. Mapping configuration card akan expand
  4. Edit JSON payload structure mapping:
    • Map incoming telemetry keys to sensor channels
    • Define data transformations
    • Set parsing rules
  5. Klik Save Mapping
  6. Klik Close untuk collapse card

Only available untuk nodes dengan assigned Node Profile

Memahami Struktur Data

3-Layer Hierarchy Explained
Node (ESP-CS-F03)
├── Sensor 1 (HIRP Power Meter)
│   ├── Channel: voltage_l1 (230.5 V)
│   ├── Channel: current_l1 (15.2 A)
│   ├── Channel: power_l1 (3500 W)
│   └── Channel: energy_total (12500 kWh)
│
├── Sensor 2 (DHT22 Temp/Humidity)
│   ├── Channel: temperature (28.5 °C)
│   └── Channel: humidity (65 %)
│
└── Sensor 3 (Ultrasonic Level)
    └── Channel: water_level (2.34 m)

Each node can have multiple sensors, each sensor can have multiple channels

Node Level Fields
  • nodeId (code): Human-readable identifier (ESP-CS-F03)
  • nodeUuid: Database UUID untuk API calls
  • idNodeProfile: Reference to node profile (if using profile-based config)
  • Owner: Company/organization yang owns node
  • Project: Project assignment
  • Model: Hardware model (ESP32-DevKit, STM32-Nucleo)
  • Protocol: Communication method (MQTT, HTTP, LoRa)
  • Firmware Version: Current firmware running on device
  • Telemetry Mode: Push (device sends) vs Pull (server queries)
  • Connectivity Status: Online, Offline, Degraded
  • Uptime: Percentage online time (last 30 days)
Sensor Level Fields
  • Sensor Code: Unique identifier within node
  • Sensor Catalog: Reference to hardware catalog (defines register map)
  • Health Status: Active (working), Inactive (not responding), Maintenance (calibration)
  • Protocol Channel: RS485 address (1-247) atau I2C address (0x48)
  • Sampling Rate: Berapa detik sekali sensor dibaca
  • Location: Physical location (inherited from node atau custom)
Channel Level Fields
  • Metric Code: Unique identifier for this measurement (voltage_l1, temp_ambient)
  • Sensor Type: Category (Temperature, Voltage, Current, Pressure, etc)
  • Unit: Measurement unit (V, A, W, °C, %, kPa)
  • Precision: Decimal places (2 = 23.45, 1 = 23.5)
  • Latest Value: Most recent telemetry reading
  • Status: OK (normal), Warning (approaching threshold), Critical (exceeded threshold)
  • Min/Max Thresholds: Alert triggering values
  • Trend: Rising, Falling, Stable (calculated from recent data)

Contoh Penggunaan

Scenario: Setup New Power Meter on Existing Node

Situasi: Install HIRP RM-3D3Y power meter baru di gateway ESP-CS-F03

Langkah:

  1. Open node detail view untuk ESP-CS-F03
  2. Klik "+ Add Sensor"
  3. Fill form:
    • Code: "SENSOR-PM-01"
    • Catalog: "HIRP RM-3D3Y" (dari dropdown)
    • Protocol Channel: "1" (RS485 address)
    • Sampling Rate: 5 (baca tiap 5 detik)
    • Status: Active
  4. Save sensor
  5. Sensor muncul, expand accordion
  6. Klik "+ Add Channel" 4x untuk add:
    • voltage_l1 (Voltage, V)
    • current_l1 (Current, A)
    • power_l1 (Power, W)
    • energy_total (Energy, kWh)
  7. Wait 5-10 seconds untuk telemetry data pertama
  8. Refresh page, latest values akan muncul di channel table

Result: Power meter fully configured, data flowing to dashboard

Scenario: Replace Faulty Sensor

Situasi: DHT22 temperature sensor rusak, ganti dengan DHT22 baru

Langkah:

  1. Expand sensor "SENSOR-DHT-01"
  2. Delete all channels (temperature, humidity)
  3. Delete sensor SENSOR-DHT-01
  4. Add sensor baru:
    • Code: "SENSOR-DHT-02" (new code)
    • Catalog: "DHT22"
    • Protocol Channel: Same as old (e.g., GPIO4)
  5. Add channels kembali (temperature, humidity)
  6. Physical: Pasang DHT22 baru di hardware
  7. Restart node
  8. Telemetry data akan flow ke channels baru

Data Loss: Historical data dari sensor lama hilang, mulai fresh dari sensor baru

Scenario: Adjust Sampling Rate untuk Save Bandwidth

Situasi: Level sensor tidak perlu real-time, slow down sampling untuk hemat bandwidth

Langkah:

  1. Find sensor "SENSOR-LEVEL-01"
  2. Klik Edit sensor
  3. Change Sampling Rate: 5s → 60s (dari tiap 5 detik ke tiap 1 menit)
  4. Save
  5. Firmware akan otomatis adjust interval (if node supports dynamic config)
  6. Monitor telemetry - should receive updates tiap 60s instead of 5s

Result: 92% reduction in telemetry traffic (60s vs 5s = 12x slower)

Scenario: Set Alert Thresholds for Critical Channel

Situasi: Voltage channel perlu alert jika drop below 200V atau spike above 250V

Langkah:

  1. Expand power meter sensor
  2. Find channel "voltage_l1"
  3. Klik Edit channel
  4. Set thresholds:
    • Min Threshold: 200
    • Max Threshold: 250
  5. Save
  6. System akan automatically generate alerts jika voltage < 200 atau > 250
  7. Alerts akan muncul di alerts module & notification

Channel status akan berubah Warning/Critical based on threshold breach

Scenario: Decommission Entire Node

Situasi: Project selesai, node ESP-CS-F03 perlu dihapus dari system

Langkah:

  1. Open node detail view
  2. For each sensor:
    • Expand sensor
    • Delete all channels (satu per satu atau bulk)
    • Delete sensor (setelah semua channels gone)
  3. After all sensors deleted, klik "Delete Node" button
  4. Confirm deletion
  5. Node removed, redirected to nodes list
  6. Physical: Power off device, uninstall hardware

Data Loss: All telemetry history, maintenance logs, configuration permanently deleted

Tips & Best Practices

Common Pitfalls:
  • Deleting sensor dengan channels: System prevent ini - harus delete channels dulu
  • Duplicate metric codes: Dalam satu sensor, metric codes harus unique - "voltage_l1" tidak bisa duplicate
  • Wrong sensor catalog: Cannot change catalog setelah sensor dibuat - plan carefully!
  • Too fast sampling: 1s interval untuk slow sensor (temp) = waste bandwidth & storage
  • No thresholds: Channels tanpa min/max thresholds tidak generate alerts
  • Forget to assign protocol channel: RS485 sensors need modbus address untuk komunikasi
Pro Tips:
  • Naming convention: Use consistent format - "SENSOR-{{ '{' }}TYPE{{ '}' }}-{{ '{' }}NUM{{ '}' }}" (SENSOR-PM-01, SENSOR-DHT-01)
  • Metric code clarity: Use descriptive codes - "voltage_l1" better than "v1"
  • Sampling rate balance: Critical sensors (voltage) = 5s, slow sensors (temp) = 60s
  • Always set thresholds: Even rough estimates untuk enable basic alerting
  • Monitor uptime badge: Quick health check - if < 95%, investigate connectivity issues
  • Use maintenance status: Set sensor to "Maintenance" during calibration untuk prevent false alerts
  • Check telemetry graphs: Top 4 sparklines show trends - spot anomalies quickly
  • Export telemetry: Before deleting channels, export data untuk archival
  • Document protocol channels: Keep spreadsheet of RS485 addresses untuk avoid conflicts
  • Test after adding: Wait 1-2 sampling intervals, refresh untuk verify data flow

Status Badges Guide
Level Status Badge Color Meaning
Sensor Health Active Green Sensor working normally
Inactive Yellow Sensor not responding
Maintenance Red Under calibration/repair
Channel Status OK Green Within thresholds
Warning Yellow Approaching threshold
Critical Red Threshold exceeded
Cascade Delete Rules
  • Delete Channel: ✅ Can delete anytime (removes telemetry history)
  • Delete Sensor: ❌ Cannot delete if has channels → Delete all channels first
  • Delete Node: ❌ Cannot delete if has sensors → Delete all sensors (& their channels) first
Keyboard Shortcuts
  • Esc - Close drawer/modal
  • Ctrl + S dalam drawer - Save changes
  • F5 - Refresh dashboard (reload fresh data)
  • Alt + ← - Back to nodes list
