Apa itu Node List?

Node List adalah halaman untuk melihat dan mengelola semua IoT Nodes (devices) yang terdaftar dalam sistem dengan table view yang lengkap.

Apa itu Node/Device?

Node adalah IoT device fisik (seperti ESP32) yang deploy di lapangan untuk mengumpulkan data dari sensors dan mengirim ke cloud platform.

Fungsi Utama:
  • Melihat semua nodes dengan detail lengkap dalam table format
  • Monitor status connectivity real-time (Online, Degraded, Offline)
  • Filter nodes by Owner, Project, dan Status
  • Search nodes by code atau project name
  • View firmware version dan telemetry mode setiap node
  • Check last seen timestamp untuk monitoring uptime
  • Pagination untuk handle large number of nodes

Cara Mengakses

Navigasi:
Sidebar Menu IoT Nodes
Role Access: Halaman ini dapat diakses oleh Super Admin, Admin, dan Owner
Alternative Access:

From Project List:

  1. Buka Project List page
  2. Click button "View Nodes" pada project card
  3. Otomatis redirect ke Node List filtered by project tersebut
  4. Badge "Filtered by Project" muncul di header

URL Path:

/iot/nodes
/iot/nodes?projectId=xxx (filtered view)

Cara Menggunakan

Filter Nodes by Status
  1. Klik tab status yang diinginkan di bagian atas table
  2. Pilih salah satu:
    • All - Tampilkan semua nodes
    • Online - Nodes yang aktif dan terkoneksi
    • Degraded - Nodes dengan koneksi tidak stabil
    • Offline - Nodes yang tidak terkoneksi
  3. Table otomatis ter-filter sesuai status
  4. Badge count update real-time dari backend statistics
Tip: Badge count Offline 3 yang tinggi = perlu investigate connectivity issues!
Filter Nodes by Owner
  1. Klik dropdown "Owner"
  2. Pilih owner dari list (contoh: PT ABC, PT XYZ)
  3. Table menampilkan nodes milik owner tersebut saja
  4. Kombinasikan dengan filter lain untuk hasil lebih spesifik
  5. Pilih "All Owners" untuk reset filter
Info: Owner list di-populate dari backend (nodes yang ada ownernya)
Filter Nodes by Project
  1. Klik dropdown "Project"
  2. Pilih project dari list
  3. Table filtered untuk nodes dalam project tersebut
  4. Berguna untuk fokus monitoring per project deployment
  5. Pilih "All Projects" untuk reset
Note: Jika masuk dari Project List → "View Nodes", filter ini otomatis set!
Search Nodes
  1. Ketik di Search Box
  2. Anda bisa search by:
    • Node code (contoh: "NODE-001")
    • Project name (contoh: "Water Treatment")
  3. Hasil muncul real-time saat mengetik
  4. Hapus text untuk clear search
Pro Tip: Kombinasi Owner + Status + Search = super targeted node finding!
Lihat Detail Node
  1. Pada table, cari node yang ingin dilihat
  2. Klik Node Code (link biru di kolom "Node")
  3. Anda akan diarahkan ke halaman Node Detail
  4. Di halaman detail, Anda bisa:
    • View informasi lengkap node
    • Manage sensors & channels
    • Configure RS485 settings
    • View telemetry history
    • Control relay (jika ada)
 Navigate dengan Pagination
Change Page Size:
  1. Klik dropdown "Rows" di bagian bawah table
  2. Pilih 10, 20, atau 50 rows per page
  3. Table otomatis update dengan page size baru
Navigate Pages:
  1. Click Previous atau Next untuk sequential navigation
  2. Click nomor halaman langsung untuk jump ke page tertentu
  3. Info "Showing X to Y of Z nodes" update otomatis
Info: Pagination client-side, load 100 nodes dari backend untuk performa optimal

Memahami Data Node

Node Data Structure:
Node (IoT Device)
├── Code: NODE-WTP-001 (unique identifier)
├── Serial Number: ESP32-A1B2C3D4
├── Status: Online / Degraded / Offline
├── Owner: PT ABC Water Solutions
├── Project: Water Treatment Plant Alpha
│
├── Firmware: v2.1.3
├── Telemetry Mode: Push (interval-based) / Pull (on-demand)
├── Last Seen: 2 minutes ago
│
└── Contains:
    ├── Multiple Sensors (Temperature, Pressure, etc.)
    ├── Multiple Channels (RS485, Analog, Digital)
    └── Optional: Relay Controls
Connectivity Status Explained:
Status Deskripsi Action Required
Online Node terkoneksi dan mengirim data normal No action needed
Degraded Node terkoneksi tapi ada issue (intermittent, slow response) Monitor closely
Offline Node tidak terkoneksi / tidak mengirim data Investigate ASAP
Telemetry Mode Explained:
PUSH Mode

Cara Kerja: Node actively mengirim data ke server berdasarkan interval (contoh: setiap 30 detik)

Keuntungan: Real-time data, proactive monitoring

Digunakan: Untuk monitoring critical parameters yang perlu update frequent

PULL Mode

Cara Kerja: Server request data dari node on-demand (node standby menunggu request)

Keuntungan: Battery efficient, bandwidth saving

Digunakan: Untuk monitoring non-critical atau battery-powered nodes

Last Seen Time Interpretation:
2 min ago ✅ Node healthy, communication normal
15 min ago ⚠️ Slightly delayed, monitor for pattern
1 hour ago ⚠️ Possible connectivity issue
1 day ago 🔴 Critical! Node likely offline, investigate immediately
Never 🆕 Newly registered node, belum pernah connect

Contoh Penggunaan

Scenario: Check Offline Nodes

Situasi: Daily morning check untuk nodes yang offline

Langkah:

  1. Klik tab Offline
  2. Lihat badge count: Offline 3
  3. Review list nodes yang offline
  4. Check "Last Seen" untuk assess severity
  5. Click node code untuk detail troubleshooting
  6. Coordinate dengan field team untuk investigate

Result: Quick identification offline nodes untuk proactive maintenance

Scenario: Monitor Project Deployment

Situasi: Anda deploy 10 nodes baru ke "Water Treatment Plant" project

Langkah:

  1. Klik dropdown "Project"
  2. Pilih "Water Treatment Plant"
  3. Table filtered untuk 10 nodes project ini
  4. Monitor status - pastikan semua "Online"
  5. Check "Last Seen" - semua < 5 min=deployment success!
  6. Export data untuk deployment report

Result: Focused monitoring untuk validate deployment success

Scenario: Find Specific Node

Situasi: Field engineer report issue dengan "NODE-WTP-005"

Langkah:

  1. Ketik WTP-005 di search box
  2. Node langsung muncul di table (instant search)
  3. Check status badge (Degraded/Offline?)
  4. Review "Last Seen" timestamp
  5. Click node code untuk buka detail page
  6. Analyze telemetry logs & sensor data

Result: Quick access untuk troubleshoot reported issue

Scenario: Owner-Specific Monitoring

Situasi: "PT ABC" owner ingin cek semua nodes mereka

Langkah:

  1. Login sebagai Owner user PT ABC
  2. Open Node List page
  3. Klik dropdown "Owner"
  4. Pilih "PT ABC" (atau sudah auto-filtered jika Owner login)
  5. View semua nodes across all PT ABC projects
  6. Check overall health: Online vs Offline count
  7. Export untuk monthly report

Result: Owner visibility untuk all their IoT infrastructure

Scenario: Firmware Update Planning

Situasi: Plan firmware update untuk nodes dengan version lama

Langkah:

  1. Open Node List (All status)
  2. Scan kolom "Firmware" di table
  3. Identify nodes dengan version < v2.0
  4. Use checkboxes untuk select nodes yang perlu update
  5. Klik "More Actions" → "Schedule Maintenance"
  6. Set maintenance window untuk firmware update
  7. Export list untuk update tracking

Result: Organized firmware update rollout plan

Tips & Best Practices

Quick Tips:
  • Daily check: Klik tab Offline untuk proactive monitoring
  • Badge count = instant health overview tanpa scroll table
  • Combine Owner + Project + Status filter = super targeted view
  • Search by partial node code (contoh: "WTP") untuk find pattern
  • Last Seen > 1 hour = perlu investigate connectivity
  • Export nodes untuk historical trend analysis
  • Use "Filter by Project" badge untuk context-aware filtering
Perhatian:
  • Offline status > 24 hours = critical issue, escalate!
  • Degraded status patterns = potential hardware/network problems
  • High offline count = possible regional connectivity issue
  • Last Seen "Never" on old nodes = registration issue or never deployed
  • Pagination loads 100 nodes max - untuk >100 use filters effectively
  • Bulk actions affect ALL selected nodes - double check before execute!
Pro Tips:
  • Morning routine: Check Offline tab → Review Degraded tab → Scan recent Last Seen
  • Access from Project List "View Nodes" untuk auto-filtered context
  • Use search untuk quick node lookup during phone support calls
  • Monitor firmware version column untuk plan rolling updates
  • Telemetry mode consistency = easier troubleshooting per project
  • Export + pivot table di Excel untuk custom analysis views
  • Bookmark page with query params untuk saved filter views
  • Status tab badge trends = KPI untuk infrastructure health
