Unpaired Devices Management Tutorial mengelola dan pairing devices yang belum terassign

Apa itu Unpaired Devices?

Unpaired Devices adalah module untuk mengelola perangkat IoT (nodes) yang sudah terdeteksi oleh platform tetapi belum di-assign ke project manapun. Module ini menyediakan interface untuk melihat list unpaired devices, detail device information, dan melakukan bulk pairing operations. Berbeda dengan User-Guide Unpaired Devices (end-user view), module ini fokus pada administrative operations dan bulk management.

Module Unpaired Devices dengan advanced filters, bulk selection, device preview, dan pairing wizard

Module Features
  • Auto-Discovery: Automatically detect devices connecting ke network (MQTT/HTTP)
  • Device Information: MAC Address, Model, Serial Number, Firmware Version, First/Last Seen
  • Advanced Filters: Status (Ready/Pending/Offline), Model, Date Range, Search
  • Bulk Operations: Select multiple devices → Bulk Pair, Bulk Ignore, Bulk Export
  • Pairing Wizard: Step-by-step wizard untuk configure device sebelum pairing
  • Device Preview: Real-time sensor detection dan channel mapping preview
  • Ignore List: Manage ignored devices untuk prevent unauthorized access
  • Historical Tracking: Track device pairing history dan status changes
Kenapa Penting?
  • Automated Onboarding: Streamline device registration tanpa manual configuration
  • Security: Admin review & approval sebelum device granted access ke production
  • Inventory Management: Track unpaired devices untuk procurement dan deployment planning
  • Bulk Efficiency: Large-scale deployments (100+ devices) dengan bulk pairing wizard
  • Troubleshooting: Identify connectivity issues dari First Seen / Last Seen timestamps
  • Firmware Compatibility: Pre-pairing firmware version check untuk prevent incompatibility

Cara Menggunakan Module

Access & Navigation
  1. Via Main Navigation
    Sidebar → Nodes section → Unpaired Devices submenu → Module page terbuka dengan list unpaired devices (default filter: Status = Ready)
  2. Via Dashboard Widget
    Dashboard → Widget Unpaired Devices Count → Click count number atau "View All" button → Navigate ke Unpaired Devices module
  3. Via Node Pairing Workflow
    Nodes List → Button + Add Node → Select From Unpaired Devices → Redirect ke Unpaired Devices module dengan pairing mode enabled
  4. Direct URL
    http://localhost:4200/iot/nodes/unpaired-devices
Admin Access Only

Permission Required: Module ini hanya accessible untuk users dengan role Admin atau Device Manager. Regular users (Viewer, Operator) tidak dapat access unpaired devices module untuk security reasons (prevent unauthorized device pairing).

2. Advanced Filters

Filter unpaired devices dengan multiple criteria:

  • Status Filter: Multi-select dropdown (All / Ready / Pending / Offline / Error) - Default: Ready only (most common use case)
  • Device Model Filter: Checkbox list dengan device count (e.g., ☑ ESP32 (15), ☑ Arduino (8), ☐ Raspberry Pi (3))
  • Firmware Version Filter: Range selector atau dropdown (Compatible only / All versions / Specific version)
  • Date Range Filter: First Seen date picker (Today / Last 7 days / Last 30 days / Custom range) - Useful untuk identify old unpaired devices (> 30 days = probably forgotten/abandoned)
  • Search: Real-time search by MAC Address atau Serial Number (useful ketika pairing specific device dari hardware inventory)
  • Sensors Filter: Filter by detected sensor types (e.g., "Has Temperature Sensor", "Has Humidity Sensor") - Useful ketika need specific sensor type untuk project
3. Bulk Operations

Manage multiple devices sekaligus (efficient untuk large deployments):

Bulk Pairing Workflow:
  1. Select Devices: Checkbox individual devices atau "Select All" (max 50 devices per batch)
  2. Click "Bulk Pair" Button: Top action bar → Pairing wizard opens
  3. Common Configuration: Wizard prompts untuk shared settings:
    • Owner selection (required)
    • Project assignment (required)
    • Location (optional - same location untuk all devices)
    • Auto-naming pattern (e.g., "NODE- counter " → NODE-001, NODE-002, etc.)
    • Sensor configuration template (apply same sensor mapping ke all)
  4. Review List: Preview table shows generated Node Codes, assigned sensors, validation status
  5. Execute Pairing: Click "Pair All" → Progress bar shows pairing status → Success notification dengan summary (e.g., "45/50 devices paired successfully, 5 failed")
Other Bulk Operations:
  • Bulk Ignore: Move selected devices ke ignore list → Prevents automatic detection (useful untuk test devices yang should not be paired)
  • Bulk Export: Download selected devices info to CSV → For inventory documentation atau offline review
  • Bulk Firmware Check: Trigger firmware version check untuk selected devices → Update firmware recommendations displayed
4. Pairing Wizard (Single Device)

Step-by-step wizard untuk pair individual device dengan full configuration:

Step Title Actions
Step 1 Device Information Review auto-detected device info (MAC, Model, Firmware, Sensors). Non-editable, for verification only. Firmware warning displayed if incompatible.
Step 2 Owner & Project Select Owner dari dropdown (required) → Project dropdown cascades (shows projects dari selected owner). Button "Create New Project" available if project tidak exist.
Step 3 Node Configuration Configure node settings:
  • Node Code: Auto-generated atau manual input (validation: uniqueness)
  • Node Name: Friendly label (required, e.g., "Temperature Sensor - Room 101")
  • Location: Text address atau map picker (optional)
  • Description: Notes (optional, max 500 chars)
Step 4 Sensor Mapping Map detected sensors ke sensor catalog:
  • Auto-detected sensors listed (e.g., "Unknown Sensor 0", "Unknown Sensor 1")
  • For each sensor → Select dari sensor catalog dropdown (e.g., DHT22 Temperature, DHT22 Humidity)
  • Configure channel mapping untuk multi-channel sensors
  • Set calibration offsets (e.g., Temperature +0.5°C correction)
Step 5 Review & Confirm Summary preview:
  • Device info (MAC, Model, Firmware)
  • Assignment (Owner, Project)
  • Node settings (Code, Name, Location)
  • Sensor configuration (Types, Channels, Calibration)
  • Validation status (all green checkmarks = ready to pair)
Click "Pair Device" button → Execute pairing → Success/Error notification
5. Device Preview

View device details tanpa pairing (inspection mode):

  • Hardware Info: MAC Address, Serial Number, Manufacturer (if available)
  • Network Info: IP Address (if DHCP assigned), Signal Strength (WiFi RSSI)
  • Firmware Details: Version, Build Date, Checksum (untuk verify integrity)
  • Sensor Detection: List detected sensors dengan raw channel data preview
  • Logs: Recent device logs (heartbeat, initialization messages, errors)
  • Actions: Reboot device (trigger remote reboot via MQTT command if online)
6. Ignore List Management

Manage ignored devices (security feature):

Ignore List Tab:
  • View Ignored: Separate tab shows all ignored devices (MAC, Ignored Date, Reason)
  • Add to Ignore: Click "Ignore" button on device → Optional reason field → Device removed from unpaired list
  • Remove from Ignore: In Ignore List tab → Click "Un-Ignore" → Device returns to unpaired list
  • Use Case: Block unauthorized devices (e.g., unknown MAC detected di network), Temporarily ignore test devices (e.g., development boards yang should not be paired to production)

Best Practices

Operational Guidelines:
  • Regular Review: Check unpaired devices list daily (atau weekly untuk small deployments). Devices dengan "First Seen > 7 days ago" should be investigated (might be forgotten devices atau test units).
  • Firmware Check First: Always verify firmware version before pairing. Incompatible firmware dapat cause telemetry failures atau system crashes. Update firmware on device before pairing if version check shows ❌ Incompatible.
  • Bulk Pairing for Large Deployments: For 10+ identical devices (same model, same sensors), use bulk pairing dengan configuration template to save time. Estimated time: ~30 seconds per device manual pairing vs ~5 seconds per device bulk pairing (6x faster).
  • Use Device Preview: Before pairing, click "Preview" untuk verify sensor detection correct. If detected sensors tidak match expected configuration (e.g., expected 3 sensors but only 2 detected), investigate device wiring atau firmware before pairing.
  • Security Review: Regularly check Ignore List untuk unauthorized devices. If unknown MAC addresses muncul frequently, investigate network security (potential unauthorized access attempts).
  • Naming Conventions: Use consistent Node Code pattern untuk easier inventory management. Examples: [Location]-[Type]-[Counter] → "JKT-TEMP-001", "SBY-HUMID-002", etc.
  • Monitor Offline Devices: Devices dengan status Offline for > 24 hours should be investigated (power issue, network connectivity problem, atau device malfunction).
Troubleshooting Common Issues:
Issue Possible Cause Solution
Device tidak muncul di unpaired list
  • Device belum connect ke network
  • MQTT broker down
  • Device firmware tidak broadcast discovery message
 Verify device power & network connection → Check MQTT broker status → Update device firmware ke latest version → Reboot device
Pairing fails dengan error "Timeout"
  • Device offline saat pairing initiated
  • Network latency high
 Verify device status = Ready sebelum pair → Check Last Seen timestamp (should be < 1 minute ago) → Retry pairing
Sensors tidak detected correctly
  • Sensor wiring incorrect
  • Firmware sensor driver issue
  • I2C/SPI address conflict
 Check device preview → View sensor logs → Verify hardware wiring → Update firmware sensor drivers → Reboot device untuk re-detect sensors
Device paired tapi tidak send telemetry
  • Sensor mapping incorrect
  • Project status = Inactive
  • Network connectivity issue post-pairing
 Navigate to Node Detail → Verify sensor mapping correct → Check Project status (must be Active) → Test network connectivity → Review node telemetry logs untuk error messages

After Pairing Devices

Post-Pairing Checklist
  1. Verify Pairing Success: Navigate to Nodes List → Filter by Project → Verify newly paired nodes visible dengan status Online
  2. Check Telemetry: Click node → View telemetry data → Verify sensor readings arriving (check Last Telemetry timestamp < 5 minutes ago)
  3. Configure Alerts: Set threshold alerts untuk critical sensors (e.g., Temperature > 35°C, Humidity < 20%)
  4. Test Remote Actions: Try remote reboot command → Verify node responds → Confirm bidirectional communication working
  5. Update Documentation: Export paired nodes list → Update inventory spreadsheet → Notify operations team device now active

Pro Tips
  • Pre-Deployment Testing: Before large deployment, test pairing workflow dengan 1-2 sample devices first. Verify sensor detection, telemetry flow, dan alert configuration working correctly before bulk pairing.
  • Firmware Standardization: Maintain consistent firmware version across all devices untuk easier troubleshooting. Create firmware update SOP (Standard Operating Procedure) sebelum pairing new batches.
  • Inventory Reconciliation: Export unpaired devices list weekly → Cross-check dengan procurement records → Identify missing devices atau unauthorized additions.
  • Automated Alerts: Set system alert untuk "Unpaired Devices Count > 10 for > 7 days" → Notify admin automatically → Ensure unpaired devices tidak forgotten.
  • MAC Address Whitelist: For high-security environments, implement MAC address whitelist → Only whitelisted MACs can appear in unpaired devices → Prevent unauthorized device auto-discovery.
  • Backup Configuration Templates: Save sensor mapping configurations as templates → Reuse untuk identical device models → Reduce pairing time by 50% (no need manual sensor mapping each time).
