Apa itu Edit Owner?

Edit Owner adalah halaman form untuk mengubah data owner yang sudah ada di dalam IoT platform. Form ini menggunakan same component dengan Create Owner, namun pre-filled dengan data existing.

Edit vs Create - Same Form, Different Mode

Component OwnersAddPage digunakan untuk both purposes:

  • Create Mode: Route /iot/owners/add → Empty form → Save button
  • Edit Mode: Route /iot/owners/edit/{{ '{' }}ownerId{{ '}' }} → Pre-filled form → Update button
  • Mode detected by presence of ownerId in route parameters
Kapan Perlu Edit Owner?
  • Contact Change: PIC (Person in Charge) resigned atau pindah posisi
  • Company Info Update: Company name change, merger, acquisition
  • SLA Upgrade/Downgrade: Contract renewal dengan different service level
  • Data Forwarding Changes: Add/remove webhook, change endpoint URL, configure database
  • Address Update: Office relocation
  • Email/Phone Update: Contact information change
  • Batch Size Tuning: Optimize data forwarding performance

Cara Akses Edit Owner Form

Ada beberapa cara untuk mengakses Edit Owner Form:

Via Owner List Page (Most Common)
  1. Navigate to IoT → Owners menu
  2. Find owner yang ingin di-edit di table
  3. Klik tombol "Edit" (pencil icon) di kolom Actions
  4. Edit Owner form akan terbuka dengan data pre-filled
Via Owner Detail View
  1. Open Owner Detail View (via owner list atau direct link)
  2. Klik tombol "Edit Project" di header atau footer
  3. Navigate to Edit Owner form
Via Direct URL

Akses langsung via browser (if you know owner UUID):

https://your-domain.com/iot/owners/edit/{{ '{' }}ownerUUID{{ '}' }}

Interface & Differences from Create

Interface Edit Owner sama dengan Create Owner, dengan beberapa perbedaan:

Key Differences from Create Mode
Aspect Create Mode Edit Mode
Page Title "Create Owner" "Edit Owner"
Breadcrumb IoT → Owners → Create IoT → Owners → Edit
Form Fields Empty (default values) Pre-filled dengan existing data
Submit Button "Save Owner" "Update Owner"
Loading State No loading (form ready) Loading spinner while fetching data (1-2 sec)
API Call POST /owners PUT /owners/{{ '{' }}id{{ '}' }}
Success Redirect Owner List (dengan highlight) Owner Detail View (show updated data)
Same Form Fields (Editable)

All fields dari Create Owner form available untuk edit:

  • Basic Info: Owner Name, Industry
  • Contact Info: Contact Person, Email, Phone
  • Service Level: SLA Level (Platinum/Gold/Silver/Bronze)
  • Additional Details: Address, Notes
  • Data Forwarding: Webhook toggle/URL, Database toggle, Batch Size

Validation rules sama dengan Create mode - required fields tetap required

Cara Menggunakan

Edit Owner Basic Information
  1. Navigate to Edit Form:
    • Go to IoT → Owners
    • Find owner (e.g., "PT ADHI WATER")
    • Klik Edit button (pencil icon)
  2. Wait for Data Loading:
    • Spinner shows: "Loading owner data..."
    • Form populates dengan existing data (1-2 seconds)
  3. Modify Fields:
    • Example 1 - Change Name:
      • Old: "PT ADHI WATER"
      • New: "PT ADHI WATER INDONESIA" (legal name change)
    • Example 2 - Change Industry:
      • Old: "Manufacturing"
      • New: "Water Treatment" (reclassification)
  4. Review Changes:
    • Check Owner Summary panel - verify new info
    • Check Payload Preview - see updated JSON
  5. Submit Update:
    • Klik "Update Owner" button
    • Button shows "Updating..." during save
    • Success → Redirect to Owner Detail View
    • Toast notification: "Owner updated successfully"

Result: Owner info updated, changes reflected di all views

Update Contact Person (PIC Change)

Scenario: Previous PIC resigned, need to update to new contact

  1. Open Edit Owner form
  2. Update Contact Fields:
    • Contact Person:
      • Old: "Budi Santoso"
      • New: "Siti Nurhaliza" (new Operations Manager)
    • Contact Email:
      • Old: "budi.santoso@adhiwater.com"
      • New: "siti.nurhaliza@adhiwater.com"
    • Contact Phone:
      • Old: "+62 812-3456-7890"
      • New: "+62 813-9876-5432"
  3. Keep other fields unchanged (name, industry, SLA, etc)
  4. Klik Update Owner
  5. System will:
    • Update owner contact info
    • Send email notification ke new contact (welcome email)
    • Update notification recipients untuk alerts & reports

Important: Verify new email valid sebelum update - akan digunakan untuk critical notifications

Upgrade/Downgrade SLA Level

Scenario: Client upgraded contract dari Gold ke Platinum SLA

  1. Open Edit Owner form
  2. Change SLA Level dropdown:
    • Old: Gold
    • New: Platinum
  3. Optionally update Notes:
    • Add: "Upgraded to Platinum SLA on Dec 24, 2025 - Contract renewal"
  4. Klik Update Owner
  5. System akan:
    • Update support priority queue (Platinum = highest priority)
    • Enable premium features (if any)
    • Update billing tier
    • Notify support team of SLA change

Response Time Changes: Platinum < 1 hour, Gold < 4 hours, Silver < 24 hours, Bronze best effort

Update Webhook Configuration

Scenario: Client changed their webhook endpoint URL

  1. Open Edit Owner form
  2. Scroll to Data Forwarding Settings section
  3. Update Webhook URL:
    • Old: "https://api.client.com/iot-data"
    • New: "https://api-v2.client.com/telemetry-webhook" (migrated to new API)
  4. Keep webhook toggle ON (already enabled)
  5. Klik Update Owner
  6. After update, verify forwarding:
    • Go to Owner Detail View → Data Forwarding tab
    • Klik Test Webhook Delivery
    • Verify success response dari new endpoint

Best Practice: Test new webhook endpoint before updating untuk avoid data delivery failures

Enable/Disable Data Forwarding

Scenario: Temporarily disable webhook due to client endpoint maintenance

  1. Open Edit Owner form
  2. Scroll to Data Forwarding Settings
  3. Toggle Enable Webhook to OFF
  4. Webhook URL field becomes grayed out (disabled)
  5. Klik Update Owner
  6. System akan:
    • Stop sending telemetry data ke webhook
    • Queue data locally (if configured)
    • Log warning: "Webhook disabled for owner X"
  7. To re-enable later:
    • Edit owner again
    • Toggle webhook back to ON
    • Verify URL still correct
    • Update & test delivery

Use Case: Temporary disable during client maintenance window, then re-enable

Tune Batch Size for Performance

Scenario: Database forwarding too slow, need to increase batch size

  1. Open Edit Owner form
  2. Current Batch Size: 100 (default)
  3. Problem Analysis:
    • High volume telemetry (1000 records/sec)
    • Small batch (100) = 10 database transactions/sec
    • Database latency high, backlog growing
  4. Solution - Increase Batch Size:
    • Change from 100 to 500
    • Result: 1000 records/sec ÷ 500 batch = 2 transactions/sec
    • Reduces database load, improves throughput
  5. Klik Update Owner
  6. Monitor Performance:
    • Check data forwarding logs di Owner Detail View
    • Verify backlog decreasing
    • If still slow, increase to 1000 (max)

Rule of Thumb: Higher volume = larger batch size (up to 1000 max)

Memahami Update Behavior

Update Behavior (Full Update)

Edit Owner uses PUT method (full replacement):

  • All fields sent: Even unchanged fields are included in payload
  • Partial update: Backend may support partial updates, but form sends all data
  • Optional fields: Can be cleared by leaving empty (e.g., remove address)
  • Required fields: Must always be provided (Name, Contact Person, Industry)
What Gets Updated
Field Group Updated? Side Effects
Owner Name ✅ Yes Updates display name across all views, breadcrumbs, dropdowns
Industry ✅ Yes Affects reporting categories, analytics grouping
Contact Info ✅ Yes Updates notification recipients, alert emails
SLA Level ✅ Yes Changes support priority, response times, feature access
Webhook Settings ✅ Yes Immediately affects data forwarding (enable/disable/change URL)
Database Settings ✅ Yes (basic toggle) Connection details configured separately di Owner Detail View
Batch Size ✅ Yes Takes effect on next batch cycle (within 1 minute)
idOwner (UUID) ❌ No (immutable) Owner ID never changes - used as primary key
Created Date ❌ No (immutable) Original creation timestamp preserved
Validation on Update

Same validation rules as Create mode apply:

  • Duplicate Name Check: New name must not conflict dengan other owners (excluding self)
  • Email Format: If provided, must be valid email
  • Batch Size Range: 1-1000
  • Webhook URL Required: If webhook enabled, URL is mandatory
  • Required Fields: Name, Contact Person, Industry - cannot be empty

Contoh Penggunaan

Scenario: Company Name Change After Merger

Situasi: PT ADHI WATER merged dengan PT TIRTA JAYA → new legal entity "PT ADHI TIRTA"

Langkah:

  1. Receive merger notification dari legal team
  2. Go to IoT → Owners
  3. Find "PT ADHI WATER", klik Edit
  4. Update fields:
    • Owner Name: "PT ADHI WATER" → "PT ADHI TIRTA"
    • Industry: Keep "Water Treatment"
    • Contact Person: Keep current (if same PIC) or update
    • Address: Update if headquarters relocated
    • Notes: Add "Merged with PT TIRTA JAYA on Dec 1, 2025"
  5. Klik Update Owner
  6. Verify changes:
    • Owner List shows new name "PT ADHI TIRTA"
    • All projects under this owner automatically show new name
    • Dashboard widgets updated
    • Reports show new name (future reports, historical retain old name)

Result: Legal entity updated, all references reflect new company name

Scenario: Fix Incorrect Contact Email (Typo)

Situasi: Owner reports tidak menerima alert emails - ternyata email typo saat create

Problem:

  • Current email: "budi.santoso@adhiwater.co" (wrong - should be .com)
  • Alerts bouncing, client complaining

Langkah Fix:

  1. Open Edit Owner form
  2. Verify issue di Contact Email field:
    • Current: "budi.santoso@adhiwater.co"
    • Correct: "budi.santoso@adhiwater.com"
  3. Fix typo: Change ".co" to ".com"
  4. Klik Update Owner
  5. Test fix:
    • Trigger test alert (or wait for next scheduled report)
    • Verify email delivered to correct address
    • Check spam folder if not received

Prevention: Always verify email during initial creation - send test email to confirm

Scenario: Migrate Webhook to Database Forwarding

Situasi: Client initially used webhook, now wants database storage untuk better analytics

Migration Plan:

  1. Phase 1 - Enable Database (Parallel):
    • Edit owner
    • Keep Enable Webhook = ON (existing)
    • Toggle Enable Database Storage = ON (new)
    • Set Batch Size = 500 (analytics optimized)
    • Update owner
  2. Configure Database Connection:
    • Go to Owner Detail View → Data Forwarding tab
    • Configure PostgreSQL connection details
    • Test connection
    • Save database config
  3. Phase 2 - Verify Database Working:
    • Monitor data forwarding logs (1-2 days)
    • Verify data flowing to PostgreSQL correctly
    • Client validates data quality
  4. Phase 3 - Disable Webhook (After Verification):
    • Edit owner again
    • Toggle Enable Webhook = OFF
    • Keep database enabled
    • Update owner

Result: Smooth migration dari webhook ke database dengan zero data loss

Scenario: Downgrade Trial to Paid Account

Situasi: Trial owner "TRIAL - ABC Manufacturing" converted to paid customer

Langkah:

  1. Edit owner "TRIAL - ABC Manufacturing"
  2. Update fields:
    • Owner Name: Remove "TRIAL - " prefix → "ABC Manufacturing"
    • SLA Level: Bronze (trial) → Gold (standard paid)
    • Contact Email: Verify & update if changed
    • Notes: Add "Converted from trial to paid on Dec 24, 2025 - 1 year contract"
    • Enable Webhook: Turn ON (production use)
    • Webhook URL: Client's production endpoint
  3. Update owner
  4. Post-conversion tasks:
    • Remove node limit (trial had max 5 nodes)
    • Enable premium features
    • Update billing system
    • Send welcome email for paid tier

Tip: Remove "TRIAL" prefix helps distinguish paid accounts di reporting

Tips & Best Practices

Common Pitfalls:
  • Changing webhook URL without testing: Can break data delivery - always test new endpoint first
  • Disabling webhook accidentally: Toggle easy to click - double check before updating
  • Not notifying client of changes: Contact info changes should be communicated
  • Changing name without updating related docs: Contracts, invoices may have old name - coordinate with legal/finance
  • Batch size too aggressive: Setting 1000 may cause memory issues if records very large - test gradually
  • Removing email accidentally: Leaving field empty removes email - verify intentional
  • SLA downgrade without notice: Client may complain if response time decreases - communicate first
Pro Tips:
  • Document changes in Notes: Add change log entries for audit trail
  • Verify email before saving: Send test email to new address to confirm valid
  • Test webhook changes immediately: After update, go to Owner Detail → Test Webhook Delivery
  • Coordinate major changes: Name/contact changes should be communicated to affected teams
  • Use parallel mode for migrations: Enable new forwarding before disabling old
  • Batch size tuning is iterative: Start conservative (100), increase gradually while monitoring
  • Keep historical notes: Don't delete old notes when updating - append new entries
  • Verify redirect after update: Should go to Owner Detail - if goes to list, may indicate error
  • Check payload preview: Before updating, verify JSON shows intended changes
  • Back button to cancel: If unsure, klik Back button instead of Update
