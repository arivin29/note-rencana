# MODBUS REGISTER MAPPING REQUEST

## KONTEKS SISTEM
Saya menggunakan ESP32 IoT device yang membaca sensor/device via RS485 Modbus RTU.
Config register disimpan dalam format JSON dengan struktur berikut:

```json
{
    "reg": 28713,           // Register address dalam DECIMAL
    "swap": false,          // true jika device pakai Little Endian
    "type": "uint16",       // Tipe: uint16, int16, uint32, int32, float32, hex16
    "unit": "Hz",           // Satuan: Hz, V, A, kW, %, °C, m³/h, dll
    "label": "Frequency",   // Nama singkat untuk display
    "scale": 0.01,          // Faktor pengali (raw × scale = actual)
    "words": 1,             // 1 untuk 16-bit, 2 untuk 32-bit
    "category": "operating_status",
    "description": "Operating frequency (U0-00, 0x7000)"
}
```

## RULES KONVERSI
1. **Hex ke Decimal**: 0x7000 = 28672, 0x100A = 4106
2. **Words**: uint16/int16/hex16 = 1, uint32/int32/float32 = 2
3. **Swap**: Default false, set true jika "Little Endian" / "Word Swap"
4. **Scale**: "Resolution 0.01" → 0.01, "Value × 10" → 0.1

## TUGAS
Generate JSON config LENGKAP:

```json
{
    "notes": "Catatan penting",
    "version": 1,
    "baud_rate": 9600,
    "registers": [ ... ],

    "description": "Deskripsi device",
    "device_type": "Device-Name",
    "modbus_address": 1,
    "scan_interval_ms": 3000
}
```

Rules Konversi
Hex ke Decimal
0x0000 = 0
0x0001 = 1
0x000A = 10
0x0064 = 100
0x03E8 = 1000
0x100A = 4106
0x7000 = 28672
0x7FFF = 32767
0xFFFF = 65535
Rumus: Setiap digit × 16^posisi
Words berdasarkan Type
uint16, int16, hex16 1 word
uint32, int32 2 words
float32 2 words
Scale dari Documentation
"Resolution 0.01" → scale: 0.01
"Value × 10" → scale: 0.1
"Value / 100" → scale: 0.01
Tidak disebutkan → scale: 1
Swap (Byte Order)
swap: false Big Endian (Default Modbus)
swap: true Little Endian / Word Swap
Set swap: true jika dokumentasi menyebut "Little Endian", "LSB First", atau "Word Swap"
Category Options
operating_status voltage current power energy temperature pressure flow analog_input digital_input fault alarm config control

Checklist Setelah Dapat Output
Troubleshooting

  • Coba toggle "swap": true / false
  • Periksa scale - mungkin perlu dikalikan/dibagi 10 atau 100
  • Cek type - mungkin seharusnya int16 bukan uint16

  • Cek register address - pastikan sudah dikonversi dari HEX ke DECIMAL
  • Cek modbus_address device (setting di device fisik)
  • Pastikan koneksi RS485 A/B tidak terbalik
  • Coba register lain yang dipastikan ada data

  • Cek baud_rate - harus sama dengan setting device
  • Cek data_format (8N1 vs 8N2 vs 8E1)
  • Coba kurangi scan_interval_ms atau tambah delay
  • Periksa kabel RS485 - jarak maksimal 1200m dengan terminator

  • Beberapa device membatasi jumlah register per request
  • Coba bagi ke multiple request dengan scan_interval_ms lebih tinggi
  • Periksa apakah register address berurutan atau ada gap
